# ПРОТОКОЛ `tickets/` — вышестоящий документ

> **Кто читает:** Ксюша (Ksyusha) в каждой сессии, до первой работы с тикетами.
> **Область действия:** вся папка `tickets/` этого монорепо.
> **Подпротоколы:**
> - [`active/ПРОТОКОЛ.md`](active/ПРОТОКОЛ.md) — очередь, приборка, проверка путей, один писатель;
> - [`active/with_lord/ПРОТОКОЛ.md`](active/with_lord/ПРОТОКОЛ.md) — папка задач владельцу (3 файла).
> При конфликте приоритет: `AGENTS.md` → этот протокол → подпротоколы.

---

## 1. Структура папки

```text
tickets/
├── ПРОТОКОЛ.md                  ← этот документ
├── active/                      ← очередь незакрытых задач
│   ├── ПРОТОКОЛ.md              ← подпротокол очереди
│   ├── <unix>-<коротко>.md      ← тикеты
│   └── with_lord/               ← задачи владельцу (ПРОТОКОЛ, СДЕЛАТЬ_ВЛАДЕЛЬЦУ, РЕШЕНИЯ_ВЛАДЕЛЬЦА)
├── Done/<ГГГГ-ММ-ДД>/           ← закрытые тикеты с доказательством, папка = дата закрытия
├── archive/<ГГГГ-ММ-ДД>/        ← обработанные не-задачи, отчёты, дубли, wip
└── deferred/                    ← отложенные владельцем; каждый файл обязан иметь строку `trigger`
```

Перед работой — `ls -1 tickets/active/`, список снимать заново, не держать в голове.

---

## 2. Обязательное правило: решения владельца → атомарные задачи

**Записано дословно по указанию владельца 15.10.2026:**

> **ОБЯЗАТЕЛЬНО!:** после записи решений и/или действий владельца создавать
> на его/их основе атомарные задачи в `tickets/active` и пометить их в очередь
> на выполнение первыми, если нет иных задач, если есть иные — добавить новую
> в хвост очереди.

Порядок применения:

1. Решение/действие владельца зафиксировано (чат, `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md`,
   вывод сервера) → **сразу** записать в `with_lord/РЕШЕНИЯ_ВЛАДЕЛЬЦА.md`
   с датой и доказательством.
2. На основе каждого решения завести **атомарный** тикет в `tickets/active/`
   (один тикет = одна правка/одна проверка, ~15 минут, проверяется отдельно).
   Составные тикеты «пять решений в одном файле» — ошибка.
3. Поставить в очередь (`active/ПРОТОКОЛ.md` §2): иных задач нет → первым;
   есть → в хвост.
4. В источнике (строка `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` / запись `РЕШЕНИЯ_ВЛАДЕЛЬЦА.md`)
   указать путь к тикету — правило 21 `AGENTS.md`.
5. Блокированные решением/файлом владельца части — не тикет, а запись
   в `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` (открытый вопрос). Тикет заводится, когда блок снят.

## 3. Формат тикета

Имя: `<unix-время>.md` или `<unix>-<коротко>.md` (unix = `date +%s` на момент
создания; внутри очереди сортировка по нему).

```markdown
# Тикет <unix> — <короткое название>

**Создан:** <дата> (unix <unix>)
**Статус:** в работе | готов | заблокирован
**Источник запроса:** <кто/откуда: чат, строка СДЕЛАТЬ_ВЛАДЕЛЬЦУ, ответ В-N>

## Цель
## Найденные факты (замеры)        ← обязательный раздел: пути/строки проверены командами
## Подзадачи
- [ ] 1. …                         ← пометки: [ ] не начат, [x] сделан+доказательство,
                                      [~] частично (что осталось), [!] заблокирован (чем)
## Критерии готовности             ← команда/артефакт, которым доказывается выполнение
## Проблемы и решения (если возникли)
## Результат                       ← вывод проверяющей команды, не пересказ намерений
```

Пометки подзадач обновляются **в файле по ходу работы**, а не в конце и не
только в чате: после потери контекста тикет — единственный источник состояния.

## 4. Жизненный цикл

| Событие | Действие |
|---|---|
| Задача взята | тикет записан в `active/` **до первой правки** |
| Выполнено и проверено | заполнить «Результат» доказательством → `git mv` в `Done/<дата закрытия>/<unix>.md` |
| Уперлось в блокер | оставить в `active/`, пометка `[!]`, в «Проблемы» — что мешает и вариант; блокер владельца → дублировать строкой в `with_lord/СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` |
| Владелец отложил | в `deferred/` со строкой `trigger`; до триггера — не начинать, не переспрашивать |
| Файл обработан, это не задача | в `archive/<дата>/` |
| Выполнено в чужом тикете | закрыть свой тикет со ссылкой на чужой (коммит/путь), не дублировать работу |

Удаление файла без переноса (Done/archive/git rm с историей) — запрещено.

---

## 5. Доказательность (без исключений)

1. `✅`, «сделано», «проверено» — только с выводом команды, путём артефакта
   или хэшем коммита рядом.
2. Факты из прошлой сессии перед повторением перепроверять текущей командой.
3. Локальная сборка ≠ прод (AGENTS, запрет выдумок п.9).
4. Слово «невозможно» запрещено: вместо него — что мешает, 2–3 варианта,
   цена, рекомендация.

---

## 6. Режимы запуска очереди (сводка; полностью — `AGENTS.md`)

| Команда | Режим |
|---|---|
| «Продолжай» | вся очередь `active/` по unix-порядку, без остановок, отчёт в конце |
| «Дальше» | ровно одна ближайшая задача: прочитать → выполнить → отметить → закрыть → выгрузить контекст → только потом следующая |
| «.» | приоритет: `работа*.md` → `Доработать*` → остальные по unix |

---

## 7. Обновление протоколов

Правила меняет только владелец явной командой. Ксюша дописывает пункты, когда
этого потребовала фактическая работа, — с датой, причиной и озвучиванием в
отчёте сессии. Расхождения фактов с записями фиксируются в том же месте, где
лежит запись, а не замалчиваются.
