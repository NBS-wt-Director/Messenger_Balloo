## 1. ⚠️ Главное: `git pull` на проде — пустая операция

Прод на ветке `fix/prisma-initial-migration-ddl`; её апстрим
`origin/fix/prisma-initial-migration-ddl` = `8befbe4`, и этот коммит **уже предок**
нынешнего `HEAD=7f14b25` (проверено `git merge-base --is-ancestor` → истина).
Поэтому `git pull` без аргументов даст `Already up to date.` и **ничего не задеплоит**
— серверный вывод это подтверждает: `behind=0` относительно апстрима текущей ветки
при `0 7` относительно `origin/main`.

Деплой делается **переходом на `main`** (§4). Это безопасно:
`git rev-list --count 97d7077..7f14b25` → **0** (на нынешнем HEAD нет ничего,
чего нет в `main`); ветка `fix/…` остаётся на `7f14b25` и служит точкой отката (ветка не тронута).

## 4. Шаг 2 — код: перейти на main и подтянуть

```bash

git show-ref --verify --quiet refs/heads/main \
  && git checkout main \
  || git checkout -b main origin/main

echo "HEAD=$(git rev-parse --short HEAD)  ветка=$(git rev-parse --abbrev-ref HEAD)"
```

Финал: `HEAD=97d7077`, `ветка=main`.

Стоп-условия (не «чинить» на месте, показывать вывод):
- первая команда напечатала список файлов вместо `(трекаемое чистое — можно)`;
- `git merge --ff-only` отказал (не fast-forward);
- `HEAD` ≠ `97d7077`.

**Не выполнять** `git clean`, `git reset --hard`, `git checkout .` — раньше тикеты
предписывали `git clean -fd`, на этой машине это снесёт untracked-файлы прод-машины.

## 5. Шаг 3 — пересобрать и пересоздать **только web**

```bash
cd /home/cfr_balloo/balloo/docker/prod
COMPOSE="docker compose -f docker-compose.local.yml --env-file .env.production"
$COMPOSE build web
$COMPOSE up -d --no-deps --force-recreate web
```

Почему именно так:
- `--no-deps` — не трогает `postgres`/`redis`/`minio`/`server` (у `web` есть
  `depends_on: server: condition: service_healthy`,
  `docker/prod/docker-compose.local.yml:186-188`);
- `--force-recreate` — обязателен: имя образа не меняется (`balloo/web:local`,
  строка 181), без флага compose может оставить старый контейнер;
- `--env-file` нужен и на `build`: `VITE_API_URL` запекается в бандль
  (`docker/Dockerfile.web:44-45`), в `.env.production` он `https://api.balloo.su`
  (строка 69);
- сборка идёт на сервере (`context: ../..`, `dockerfile: docker/Dockerfile.web`,
  строки 174-181): `pnpm install --frozen-lockfile` + `vite build`
  (`docker/Dockerfile.web:22-48`), штатно 3–10 минут.

Стоп-сигналы: ошибка `pnpm install --frozen-lockfile` или `vite build` → контейнер
не пересоздан, прод живёт на старом образе; вывод в чат.

## 9. Чего в этом деплое нельзя

| Запрет | Причина |
|---|---|
| `docker compose down`, `rm`, `docker network prune/rm` | сеть `balloo-net` с `172.19.0.0/16 gw 172.19.0.1` закреплена (`docker/prod/docker-compose.local.yml:258-269`); шлюз = `SMTP_HOST` postfix-релея, пересоздание молча ломает почту |
| `up -d --build` на весь стек | меняется только `web`; пересоздание `server`/`postgres` = простой БД и разрыв WS |
| `systemctl restart balloo` как способ передеплоить | юнит зовёт `/usr/local/bin/balloo-deploy.sh`, а тот делает `up -d --remove-orphans` **без `--build`** (`deploy/balloo-deploy.sh:50`) — новый код не соберётся |
| `systemctl restart docker` (висит в отложенных `needrestart` после установки `tree`) | перезапуск демона уронит весь стек |
| миграции / `prisma db push` | в диапазоне миграций нет (§2) |
| правки `.env.production`, nginx, CORS | не менялись в диапазоне (§2) |
| `git clean -fd` / `git reset --hard` / `git checkout .` | снесут untracked-файлы прод-машины |
| `docker builder prune -a` | Dockerfile.web живёт на cache-маунтах pnpm-store и prisma-engines (`docker/Dockerfile.web:22-29`); сброс = долгая сборка без пользы. Свободных 15G хватает |
