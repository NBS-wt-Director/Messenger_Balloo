# Тикет 1795101593 — Коды авторизации через push/email: механизма нет (ПРОВЕРИТЬ)

**Создан:** 19.11.2026 (unix 1795101593)
**Статус:** ждёт решения владельца (не начинать без ответа)
**Источник запроса:** владелец 19.11.2026: «коды авторизации доходят из push?»

## Ответ на вопрос владельца (замер)

**Механизма кодов авторизации через push (или email) не существует.** Что есть:

| Механизм | Состояние | Доказательство |
|---|---|---|
| 2FA при входе | ✅ есть, но **только TOTP** | `authService.verify2FA` (`:415`) проверяет TOTP-код (`verifyTOTP`) + backup codes. Код берётся из приложения-аутентификатора (Google Authenticator и т.п.), не из push |
| Включение 2FA | ✅ есть | `enable2FA` возвращает `qrCodeUrl` — `otpauth://totp/...` (`authService.ts:1174`), `authController.ts:677` |
| Код в push при входе | ❌ нет | `loginService` (`:307–346`) при включённой 2FA возвращает `requires2FA` и всё; отправки кода по push/email нет |
| Код на email при входе | ❌ нет | email-сервис (`emailService.ts`) шлёт только подтверждение регистрации/сброс пароля |
| Push как «подтвердить вход» | ❌ нет | push-инфраструктура есть (browser push, mobile FCM-задел), но в поток авторизации не включена |

**Следствие:** «код из push» пользователь получить не может — такого кода нет.
Единственный второй фактор — TOTP-приложение.

## Что решить владельцу (вопрос, а не задача)

Нужен ли **push-подтверждаемый вход** (как в Telegram: «Подтвердите вход» на
доверенном устройстве) или **одноразовый код в push/email** как второй фактор?

| Вариант | Что это | Цена | Риск |
|---|---|---|---|
| (а) Оставить как есть | 2FA = TOTP-приложение | 0 | часть пользователей не заведёт TOTP |
| (б) Push-подтверждение входа | новое устройство → push на доверенное → «Подтвердить» → вход | средняя: mobile push + экран подтверждения + связь с QR-flow (тик. 1795101592) | нужен работающий mobile push (FCM вне MVP1 по решению владельца) |
| (в) Код на email | письмо с 6-значным кодом при входе | низкая: SMTP + шаблон + верификация кода | **SMTP ещё не настроен** (нет живой отправки, SPF/DKIM) |

**Рекомендация:** для MVP1 — вариант (а). Варианты (б)/(в) — после запуска:
(б) требует FCM (отложен владельцем), (в) требует SMTP (не настроен).
