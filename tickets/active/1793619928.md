# Тикет 1793619928 — balloo.su недоступен из браузера: DNS-хостинг beget не отвечает (прод жив)

**Создан:** 2026-11-02 16:45 +05 (unix 1793619928)
**Статус:** заблокирован — зависит от провайдера DNS (beget), действия владельца в `with_lord/1793619928-dns-beget.md`
**Источник запроса:** сообщение владельца: браузер → `balloo.su` → «Не удаётся установить соединение с сайтом, Время ожидания ответа истекло. Код ошибки: ERR_TIMED_OUT»

## Цель

Объяснить запуском (а не догадками), почему сайт не открывается, и separated
это от состояния прода; дать владельцу обход, чтобы браузерная приёмка MVP1
не теряла дни.

## Диагноз (доказано прогонами 02.11.2026 16:3x–16:4x)

**Сервер жив.** Все проверки через `--resolve <host>:443:188.73.176.34` (без `-k`,
т.е. TLS валиден):

| Хост | Ответ |
|---|---|
| `balloo.su` | **200** |
| `api.balloo.su` | **200** |
| `admin.balloo.su` | **200** |
| `cdn.balloo.su` | **403** (MinIO через nginx, анонимный листинг закрыт намеренно) |

TCP 80 и 443 на `188.73.176.34` — **открыты** (проверка `/dev/tcp`).

**Ломается DNS-цепочка.** По шагам:

1. `dns.google/resolve?name=balloo.su&type=A` → `Status=2` (SERVFAIL); то же у
   Cloudflare DoH (`cloudflare-dns.com`) для `A`, `NS`, `SOA`. Контроль того же
   метода: `google.com|A` → `Status=0` с 6 адресами — резолверы работают,
   проблема не в моле сети.
2. Google DoH прямо называет причину:
   `Name servers did not respond [ns2.beget.pro.(93.92.81.0), ns2.beget.pro.(5.101.159.11)]`
   (комментарий сервиса, не моя интерпретация).
3. Делегирование **корректно** — TLD `.su` (a/b/c…dns.ripn.net / c.tld-servers.ru,
   отвечают с флагом `aa`) отдаёт:
   `balloo.su. NS ns1.beget.ru / ns1.beget.com / ns1.beget.pro / ns2.beget.*`
   Glue: `ns1.beget.ru` = 5.101.159.11, 93.92.81.0; `ns2.beget.ru` = 185.50.27.12, 194.113.245.0.
4. **Сами NS beget не отвечают.** Прямые запросы к glue-IP: UDP — пусто,
   TCP — `timed out`; `/dev/tcp/<ip>/53` → закрыт/таймаут на всех четырёх адресах.
   Метод контроля: тем же способом TLD-серверы `.su` отвечают (`NOERROR`, `aa`).
5. Масштаб — **не только наша зона**: `beget.ru`, `panel.beget.ru`, `www.beget.ru`,
   `beget.com`, `www.beget.com`, `panel.beget.com` → тоже SERVFAIL. Их собственная
   зона лежит вместе с клиентскими.
6. Кто отдаёт ERR_TIMED_OUT в браузере: рекурсор провайдера ждёт ответа NS до
   своего дедлайна (`Unable to resolve query within internal deadline` у Google) →
   клиент ждёт резолвер → браузер показывает таймаут, а не `ERR_NAME_NOT_RESOLVED`.
   Это согласуется с симптомом владельца.

**whois-факты (TCP 43 к `whois.ripn.net`, TCI):**

```
domain:  BALLOO.SU
nserver: ns1.beget.ru / ns1.beget.com / ns1.beget.pro / ns2.* (6)
state:   REGISTERED, DELEGATED, UNVERIFIED
registrar: BEGET-SU
admin-contact: https://beget.com/ru/domains/contact
created: 2025-11-08   paid-till: 2026-11-08   free-date: 2026-12-11
```

То есть домен **оплачен и делегирован** (не изъят), статус `UNVERIFIED` — данные
владельца в зоне .su не верифицированы; оплата действует до **08.11.2026**.
Это факт из whois, а не прогноз: продление и верификация — отдельная задача
владельцу, к текущему сбою отношения не имеют (NS не отвечают при действующей
оплате).

## Вывод

**Деплой ни при чём, откат не нужен, код не при чём.** `balloo-server`, `balloo-web`,
`balloo-web-admin`, `minio` работают и отдают правильный код (см. `1793435849`,
`1793567633`). Недоступен только публичный DNS зоны, который хостится у beget, —
внешняя зависимость, у меня нет ни доступа к панели beget, ни возможности её дождаться.

- В тикете записан вывод повторной проверки.

## Проблемы и решения

- **Моя сеть:** исходящий **UDP 53** к публичным резолверам не проходит
  (`dig @1.1.1.1` → таймаут к `127.0.0.53#53`), поэтому обычный `dig +short`
  бесполезен на этой машине. Решение: DoH через `curl` (`dns.google`,
  `cloudflare-dns.com`) и `dig +tcp` к конкретным серверам. **Правило:** проверку
  DNS делать по цепочке (рекурсор → TLD → NS по glue IP), а не одним `dig`,
  иначе SERVFAIL выглядит как «домена не существует».
- **Не выдумываю содержимое зоны:** полной копии DNS-записей `balloo.su` у нас нет —
  `docs/15-domains.md:100` прямо говорит «DNS-записи зоны приложит владелец»,
  выгрузки из панели beget в репозитории нет. Поэтому набор A-записей в п.7 —
  это **список требуемых имён из кода и nginx**, а не утверждение, что в зоне
  было ровно столько записей. MX/TXT (почта, SPF/DKIM/DMARC) при переносе
  **обязательно** выгружаются из панели beget — их значений у меня нет.
- Не предлагаю ротацию секретов и «чистку» — решения владельца №1/№3 в силе; DNS
  к ним не относится.

## Результат

Причина недоступности сайта установлена и доказана: **авторитетные NS-серверы
beget (`ns1/ns2.beget.ru|.com|.pro`) не отвечают ни по UDP, ни по TCP**, из-за чего
публичные рекурсоры отдают SERVFAIL для всей зоны `balloo.su` (и для самих зон
beget). Прод работает: по IP все четыре хоста отдают 200/403 с валидным TLS.
Блокировка внешняя; приёмка MVP1 возможна сегодня через hosts-обход — команды в
`with_lord/1793619928-dns-beget.md`.
