## Цель

По решению В-109: существующие поддомены (app, admin, command, api) — вариант **Б**
(один web + `server_name` в nginx); новые и тестовые (features, history, download,
docs, specifity, blog) — вариант **А** (отдельный контейнер + порт на каждый).
«Задел» = структура compose должна допускать переход старых поддоменов на А **без
переписывания**: отдельный env-файл на каждый сервис, монитор/health-check из
шаблона, шаблоны vhost.

## Найденные факты (замеры 15.10.2026)

1. Отдельные сервисы в `docker/prod/docker-compose.local.yml`: `server` (:105),
   `web` (:190), `features` (:212). То есть **вариант А для `features` уже реализован**.
2. `docker/prod/nginx-production.conf`: `features.balloo.su` — отдельный `server{}`
   c `features_backend` (:127); остальные поддомены — один общий `server{}` (:175)
   с `web_backend`. То есть history/download/docs/blog/admin/command живут на **Б**.
3. Отдельных env-файлов на сервис **нет** — один `docker/prod/.env.production`
   (`ls docker/prod/*.env` → пусто).
4. MVP1 = `balloo.su` + `api.balloo.su` + `history.balloo.su` + `download.balloo.su`
   + desktop + Android (`PROJECT_DOCUMENTATION.md` §17). Features/docs/blog/specifity
   в MVP1 **не входят**.

## Подзадачи

- [ ] 1. Шаблон env-файла на сервис (`docker/prod/env/<service>.env`), без раскатки.
- [ ] 2. Шаблон compose-сервиса (SPA-контейнер + порт + health-check) — один файл-заготовка.
- [ ] 3. Шаблон vhost nginx (443 + TLS + прокси на сервис) — заготовка для новых поддоменов.
- [ ] 4. Сверить, что переход app/admin/command на вариант А не требует переписывания
      существующих сервисов (проверка по шаблонам, не по памяти).

## Критерии готовности

Шаблоны лежат в `docker/prod/`, `docker compose config` валиден с подключённым
шаблоном (сухой прогон, без пересоздания контейнеров), текущий прод-стек не изменён.
