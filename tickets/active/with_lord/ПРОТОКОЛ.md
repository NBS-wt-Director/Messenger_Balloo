# 📋 ПРОТОКОЛ `with_lord/` — инструкция для Ксюши

> **Кто читает:** Ксюша (AI-ассистент) в каждой новой сессии, до первой работы с
> папкой. Цель — работать по `with_lord/` одинаково между сессиями, без
> объяснений владельца.
> **Что здесь:** только правила ведения папки. Задачи владельца — в
> `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md`, принятые решения — в `РЕШЕНИЯ_ВЛАДЕЛЬЦА.md`.

---

## 1. Состав папки — ровно три файла

| Файл | Кто пишет | Назначение |
|---|---|---|
| `ПРОТОКОЛ.md` | Ксюша | этот файл: правила ведения папки |
| `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` | Ксюша заводит, владелец заполняет | всё, что Ксюша не может сделать сама: решения с вариантами, приёмка, ключи/файлы, команды на сервере, совместная работа, тестирование |
| `РЕШЕНИЯ_ВЛАДЕЛЬЦА.md` | Ксюша | зафиксированные решения и выполненные владельцем задачи; источник для постановки своих тикетов |

**Четвёртых файлов здесь нет.** Отдельный тикет-блокер создаётся в
`tickets/active/<unix>.md`, а в `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` остаётся одна строка со
ссылкой на него. Служебные выгрузки (`.txt`, выжимки, черновики) в папку не
складываются.

---

## 2. Порядок чтения на старте сессии

1. `ls -1 tickets/active/with_lord/` — убедиться, что файлов ровно три.
2. Прочитать `РЕШЕНИЯ_ВЛАДЕЛЬЦА.md` — это константы. Их **не переспрашивать** и
   не предлагать пересмотр (см. также «Решения владельца» в `AGENTS.md`).
3. Прочитать `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` сверху вниз, блоками по фазе.
4. По каждой строке проверить состояние **командой или чтением артефакта**, а не
   по памяти из прошлой сессии (`AGENTS.md` §0: код проверяется запуском).
5. Всё, что владелец уже ответил/сделал, превратить в задачу немедленно:
   тикет в `tickets/active/<unix>.md` + запись в `РЕШЕНИЯ_ВЛАДЕЛЬЦА.md`
   (`AGENTS.md`, быстрое правило 21).

## 3. Структура `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` — шесть блоков по фазе

| Блок | Что внутри |
|---|---|
| **1. До деплоя MVP1** | приёмка макетов MVP1 и всё, что относится к MVP1: артефакты сборок, ключи, TLS/DNS, настройки сервера, решения с вариантами |
| **2. Деплой MVP1** | команда «Деплой», батчи на сервер, DNS/сертификаты/seed, входящие в деплой |
| **3. Тестирование MVP1** | подтверждение вывода сервера, браузерный чек-лист, приёмка сборок и поддоменов |
| **4. Публикация MVP1** | выкладка артефактов (APK, desktop), релизный тег, открытие регистрации |
| **5. Всё остальное** | не блокирует MVP1: SMTP/DKIM, OAuth, бэкапы, Метрика, CSP |
| **6. Принятые и обработанные решения и выполненные задачи** | архив: всё, что закрыто в Блоках 1–5, перенесено сюда с датой и доказательством |

Порядок внутри блока — по критичности: сначала то, без чего фаза не закрывается.

## 4. Формат задачи владельцу

Одна задача = одна табличная строка:

```markdown
| № | Что нужно | Сделано | Решение |
|---|---|---|---|
| 1.4.1 | Перевыпустить сертификат с `-d history.balloo.su` | | |
```

Обязательные элементы:

- **Зачем** — 1–2 строки над таблицей: что блокируется без этого пункта.
- **Сделано** — поле владельца; Ксюша заполняет его только когда выполнение
  доказано командой, и тогда пишет результат замера + дату, а не «сделано».
- **Решение** — поле владельца; если есть выбор, Ксюша заранее вписывает
  варианты и рекомендацию: `(а) … / (б) … — рекомендую (а), потому что …`.
- **Команды** — если задача серверная или локальная, готовый блок `bash`
  готовым к копированию, ≤15 строк, с ожидаемым выводом. Серверные команды
  выполняет только владелец (`AGENTS.md`, решение №7).
- **Ссылка на тикет** — если по задаче заведён тикет, в строке путь к нему.

Номера строк — `<блок>.<подраздел>.<номер>`, сквозные и не меняются.

## 5. Пометки состояния

| Пометка | Значение |
|---|---|
| пусто | ждёт владельца |
| `✅` + дата + доказательство | сделано и проверено |
| `[~]` / «частично» | сделано частично — дописать что осталось |
| `❌` + причина | заблокировано — дописать чем и вариант обхода |
| `—` | не потребовалось (закрылось другим путём) |
| `➡️ 6.x` | **перенесено в Блок 6** (строка закрыта, доказательство в Блоке 6) |

`✅` ставится только вместе с доказательством: вывод команды, путь артефакта,
хэш коммита. Голый `✅` — это выдумка (`AGENTS.md`, «Запрет на выдумки»).

**Правило переноса:** когда строка в Блоке 1–5 получает `✅` с доказательством,
следующая сессия (Ксюша) переносит её целиком в Блок 6 с тем же номером и датой,
а в исходной строке Блока 1–5 заменяет на `➡️ 6.x`. Исходная строка не удаляется
молча — в ней остаётся номер и ссылка на Блок 6.

## 6. Как Ксюша обрабатывает заполненные поля

| Владелец вписал | Действие Ксюши |
|---|---|
| букву варианта (`а`/`б`) | записать в `РЕШЕНИЯ_ВЛАДЕЛЬЦА.md`, завести тикет, выполнить |
| значение/ключ | проверить чтением конфига или запросом, завести тикет |
| «сделано» по серверной команде | запросить вывод; без вывода статус остаётся «не подтверждено» |
| отметку приёмки (`принято` / `не принято: …`) | внести статус в `mockups/index_ecrans.*`; правки → отдельный тикет |
| «не нужно» / «потом» | записать решение с триггером, задачу снять с критического пути |
| `✅` + доказательство | **перенести строку в Блок 6** с тем же номером и датой; в исходной строке Блока 1–5 заменить на `➡️ 6.x` |

После обработки строка не удаляется молча: переносится в Блок 6 (с доказательством)
или остаётся в Блоках 1–5 с пометкой `➡️ 6.x`.

## 7. Границы

1. **Не предлагать ротацию секретов** ни в каком виде — решение владельца №1.
2. **Не считать ЮKassa блокером** — решение №4.
3. **Не планировать код-ревью и онбординг** — команда двое, решение №5.
4. **Не заходить на сервер** — SSH-доступа нет, команды печатает Ксюша,
   выполняет владелец.
5. **Не трогать `tickets/deferred/`** без наступления `trigger`.
6. **Не плодить реестры**: вопросы владельцу живут только в
   `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` (Блоки 1–5), ответы-константы — в `РЕШЕНИЯ_ВЛАДЕЛЬЦА.md`,
   архив закрытых задач — в `СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md` Блок 6.
7. **Номера В-N** (В-1…В-118) — наследие реестра `ВОПРОСЫ_ВЛАДЕЛЬЦУ.md`,
   удалённого 15.10.2026 и объединённого с `with_lord/`. В архивных тикетах
   (до 15.10) вопросы названы этими номерами — соответствие читать в
   `РЕШЕНИЯ_ВЛАДЕЛЬЦА.md`, раздел 10. Номера не переиспользовать и не выдумывать
   новые: в реестре их было ровно 118 (номера вида «В-129…В-132» в старых файлах
   реестра не имели).

## 8. Обновление этого протокола

Правила меняет только владелец явной командой. Ксюша вправе дописывать пункты,
если этого потребовала фактическая работа, — с датой и причиной, и обязательно
озвучивает правку в отчёте сессии. Изменения, противоречащие `AGENTS.md`,
недействительны: приоритет у `AGENTS.md`.
