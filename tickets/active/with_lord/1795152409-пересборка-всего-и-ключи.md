## Часть C. Найдено попутно: клиентский кэш не инвалидируется (моя работа)

При проверке причин «старого меню» найдено два дефекта в кэшировании фронта:

1. **`packages/web/public/sw.js`:** `CACHE_NAME = 'balloo-v1'` **не меняется** между
   сборками, а статика отдаётся стратегией **Cache First** (`cacheFirst`). Значит
   закэшированные ассеты живут в браузере до ручного сброса SW.
2. **`docker/nginx.conf`:** для `index.html` не выставлен `Cache-Control`
   (нет `no-cache`/`no-store`), хотя для хешированных ассетов это норм. `curl -sI
   https://balloo.su/` → `Cache-Control` отсутствует, есть только `ETag`/`Last-Modified`.

**Следствие:** после деплоя клиент может держать старую версию до жёсткого сброса
(DevTools → Application → Service Workers → Unregister → Ctrl+Shift+R). Это ровно
то, что видит владелец.

**План (моя работа, отдельным тикетом):** версионировать `CACHE_NAME`
(`balloo-v2` при каждом релизе либо хэш сборки) + добавить в `docker/nginx.conf`
`location = /index.html { add_header Cache-Control "no-cache"; }` и длинный
`immutable`-кэш для `/assets/`.
