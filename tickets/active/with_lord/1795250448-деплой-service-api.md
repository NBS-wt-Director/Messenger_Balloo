# 1795250448 — Деплой: Service API `/api/service/*` на прод

**Создан:** 2026-11-21 (unix 1795250448)
**Тип:** деплой (батчи выполняет владелец — у ассистента нет SSH-доступа)
**Блокирует:** использование сервисных эмуляционных эндпоинтов на проде

## Что меняется

Серверные эмуляционные эндпоинты `/api/service/*`, закрытые длинным ключом
(`SERVICE_API_KEY`, заголовок `X-Service-Key`). Фронтенд НЕ меняется — деплоится
только контейнер `server` (API). Порядок по KODA.md «сначала API, затем web»:
web можно не пересобирать, т.к. его код не тронут.

Изменённые файлы:
- `packages/server/src/middleware/serviceAuth.ts` (новый)
- `packages/server/src/controllers/serviceController.ts` (новый)
- `packages/server/src/routes/service.ts` (новый)
- `packages/server/src/routes/index.ts`, `config/env.ts`, `middleware/rateLimit.ts`
- `docker/prod/docker-compose.local.yml`, `docker-compose.prod.yml` (проброс `SERVICE_API_KEY`)
- `.env.production.example` (заготовка ключа), `.gitignore` (`docs/local/`)
- `scripts/server_routes.txt` (перегенерация дампа, 293 маршрута)

## ВАЖНО: ключ на проде

`SERVICE_API_KEY` **отсутствует** в `docker/prod/.env.production` — его надо
добавить на сервере (батч E). Без него все `/api/service/*` отвечают `404`
(фича выключена — это безопасно, но эмуляция не работает).

- Сгенерировать на сервере: `openssl rand -hex 32`
- Добавить строку `SERVICE_API_KEY=<значение>` в `docker/prod/.env.production`
- Значение — только на сервере и в локальном `docs/local/service-api.md` (вне git)

**Батч E — ключ + бэкап БД**
```bash
cd /data/balloo/repo/docker/prod
# 1) ключ (если ещё не задан)
grep -q '^SERVICE_API_KEY=' .env.production || echo "SERVICE_API_KEY=$(openssl rand -hex 32)" >> .env.production
grep '^SERVICE_API_KEY=' .env.production
# 2) бэкап БД
mkdir -p backups && docker exec balloo-postgres pg_dump -U balloo balloo > backups/pre-service-api-$(date +%F-%H%M).sql && ls -lh backups | tail -2
```

**Батч F — сборка и перезапуск ТОЛЬКО server**
```bash
cd /data/balloo/repo/docker/prod
docker compose -f docker-compose.local.yml --env-file .env.production build server
docker compose -f docker-compose.local.yml --env-file .env.production up -d --no-deps --force-recreate server
sleep 20 && docker compose -f docker-compose.local.yml --env-file .env.production ps server
```

**Батч G — доказательства**
```bash
cd /data/balloo/repo/docker/prod
docker compose -f docker-compose.local.yml --env-file .env.production logs --tail=40 server
curl -s -o /dev/null -w "health=%{http_code}\n" http://127.0.0.1:3100/health
KEY=$(grep '^SERVICE_API_KEY=' .env.production | cut -d= -f2)
curl -s -o /dev/null -w "no_key=%{http_code}\n" http://127.0.0.1:3100/api/service/users
curl -s -H "X-Service-Key: $KEY" http://127.0.0.1:3100/api/service/health
curl -s -H "X-Service-Key: $KEY" "http://127.0.0.1:3100/api/service/users?limit=1" | head -c 300; echo
curl -s -o /dev/null -w "public_api=%{http_code}\n" https://api.balloo.su/health
```

Ожидаемо: `no_key=401`, `/api/service/health` → `{"ok":true,...}`, `public_api=200`.

**Батч H — приёмка владельца**
Проверить из браузера/curl, что боевой сайт открывается и вход работает.
Эмуляцию на проде проверяем `curl` с ключом (см. `docs/local/service-api.md`).

## Критерий закрытия

Батч G показывает `no_key=401`, `/api/service/health` → `{"ok":true}`, `public_api=200`;
плюс браузерная приёмка владельца (батч H). Без обоих — статус «не подтверждено».
