# ❗ DNS-хостинг beget не отвечает — balloo.su не резолвится

**Создан:** 02.11.2026 (unix 1793619928)
**Статус:** ждёт владельца (внешняя зависимость, не мой блок)
**Источник:** `tickets/active/1793619928.md` — диагностика DNS-цепочки

---

## Что происходит

**Прод жив** (все четыре хоста отдают 200/403 с валидным TLS), но браузер
показывает `ERR_TIMED_OUT`. Причина: авторитетные NS-серверы зоны
`balloo.su` (beget) не отвечают ни по UDP, ни по TCP.

**Доказано:**
- `dig +tcp @5.101.159.11 balloo.su A` → `Connection timed out`
- `/dev/tcp/5.101.159.11/53` → закрыт/таймаут
- `cloudflare-dns.com/dns-query?name=balloo.su&type=A` → `Status=2` (SERVFAIL)
- Google DoH прямо пишет: `Name servers did not respond [ns2.beget.pro.(93.92.81.0), ns2.beget.pro.(5.101.159.11)]`
- `beget.ru`, `panel.beget.ru`, `beget.com` — тоже SERVFAIL (провайдерский сбой)

**whois-факты (TCP 43, `whois.ripn.net`):**
- `state: REGISTERED, DELEGATED, UNVERIFIED`
- `registrar: BEGET-SU`
- `paid-till: 2026-11-08` (через 6 дней)
- домен оплачен и делегирован, **не изъят**

## Что сделать сейчас: обход через `/etc/hosts` (чтобы приёмка MVP1 не ждала)

Это **временный обход** (до восстановления beget или переноса зоны). Не требует
доступа к серверу — делается на **вашей машине**, где открывается браузер.

### Linux (Ubuntu / рабочий стол)

```bash
```bash
# Нужны права администратора (sudo). Одна строка — все имена с валидным TLS:
echo "188.73.176.34 balloo.su api.balloo.su www.api.balloo.su admin.balloo.su cdn.balloo.su" | sudo tee -a /etc/hosts
```

**`www.balloo.su` в список не включать** — его нет в SAN сертификата (замер
02.11.2026), браузер покажет ошибку сертификата; редирект работает в сторону
`balloo.su`, а не наоборот.
```

### Windows (если принимаете с другой машины)

Открыть **Notepad от имени администратора** и в конец `C:\Windows\System32\drivers\etc\hosts`
добавить строки:

```
188.73.176.34 balloo.su
188.73.176.34 api.balloo.su www.api.balloo.su
188.73.176.34 admin.balloo.su
188.73.176.34 cdn.balloo.su
```

Затем `ipconfig /flushdns`.

### КРИТИЧНО: отключить Secure DNS в браузере

Chrome/Edge **игнорирует** `/etc/hosts` при включённом «Безопасном DNS»:
1. **Настройки → Конфиденциальность и безопасность → Безопасный DNS**
2. **Отключить** (выбрать «По умолчанию» или «Выключить»)
3. Полностью закрыть и открыть браузер заново

Без этого DNS-кэш браузера всё равно пойдёт на внешний DoH → SERVFAIL.

### Проверка

```bash
# после правки /etc/hosts:
curl -sS -o /dev/null -w "balloo.su http=%{http_code}\n" https://balloo.su/
curl -sS -o /dev/null -w "api.balloo.su http=%{http_code}\n" https://api.balloo.su/
curl -sS -o /dev/null -w "admin.balloo.su http=%{http_code}\n" https://admin.balloo.su/
```

Ожидаю: **200, 200, 200**. Если 200 — браузерная приёмка MVP1 доступна.

## Что делать с зоной (длинная перспектива)

Домен `balloo.su` зарегистрирован у **BEGET-SU**, NS делегированы на beget.
Если beget не восстановит NS в течение 24–48 часов, есть два пути:

1. **Написать в поддержку beget** — `https://beget.com/ru/domains/contact`
   (их сайт, возможно, доступен через IP или когда DNS-зона восстановится).
   Спросить: «ns1/ns2.beget.ru не отвечают — когда будет восстановление?».
   Это их инфраструктура, они могут перенести NS на рабочие серверы.

2. **Перенести NS зоны balloo.su** на другой DNS-хостинг (Cloudflare,
   Selectel, Яндекс.Облако, регистратора nic.ru). Для этого:
   - Зайти в панель beget (когда станет доступной)
   - Сменить NS зоны balloo.su на NS нового хостинга
   - Или перенести домен к другому регистратору (не быстро)
   - **Обязательно выгрузить MX/TXT/SPF/DKIM/DMARC** — их значений у меня нет,
     без них почта на домене не будет работать

**Пример реестра A-записей для нового хостинга** (полный список в
`docs/15-domains.md:98`, ниже краткая справка):

| Хост | Запись | Тип |
|---|---|---|
| `@` (balloo.su) | `188.73.176.34` | A |
| `www` | `188.73.176.34` | A |
| `api` | `188.73.176.34` | A |
| `admin` | `188.73.176.34` | A |
| `cdn` | `188.73.176.34` | A |
| `app` | `188.73.176.34` | A |
| `features` | `188.73.176.34` | A (но TLS-сертификат на alpha.balloo.su → 502) |
| `history` | `188.73.176.34` | A |
| `download` | `188.73.176.34` | A |
| `docs` | `188.73.176.34` | A |
| `blog` | `188.73.176.34` | A |
| `command` | `188.73.176.34` | A |

MX, TXT, SPF, DKIM, DMARC — **не выдумываю**: значений нет в репозитории,
надо выгружать из панели beget.

## Чего НЕ делать

- **Не откатывать образ** `balloo-server` — откат не поможет (проблема не в коде)
- **Не пересобирать фронты** — фронты соответствуют HEAD (0 коммитов после 29.10)
- **Не трогать БД/сервисы** — всё работает, перебой только в DNS
