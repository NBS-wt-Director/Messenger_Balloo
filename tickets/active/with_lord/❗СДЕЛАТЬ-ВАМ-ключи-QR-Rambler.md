## 4. `VAPID_PUBLIC_KEY` в `.env.production` — значение невалидно (замерено 02.11.2026)

**Факт, а не подозрение.** Замер длины после base64url-декодирования (значения
не печатались):

| Переменная | Символов | Байт | Требуется | Итог |
|---|---|---|---|---|
| `VAPID_PRIVATE_KEY` | 43 | **32** | 32 | ✓ корректной длины |
| `VAPID_PUBLIC_KEY` | 43 | **32** | **65** (несжатая точка P-256) | ✗ не VAPID-ключ |

Живой прогон `web-push@3.6.7` на этих же значениях:
`setVapidDetails(...)` → `Error: Vapid public key should be 65 bytes long when
decoded.` Контроль: пара от `webpush.generateVAPIDKeys()` даёт `publicKey
chars=87 bytes=65` и принимается.

**Чем это обернулось.** 02.11.2026 при деплое `3f627c5` модуль `pushService.ts`
впервые попал в граф импортов запуска (цепочка `routes/index → devices →
deviceController`, коммит `115d872` от 13.10.2026) — бросок на верхнем уровне
останавливал процесс до `listen()`, `balloo-server` ушёл в crash-loop. Сервер
починен так, что битые ключи только отключают browser push (тикет
`active/1793615244`), то есть **деплой от этого больше не зависит**.

**Что нужно от вас (только вы).** Найти настоящий публичный ключ этой пары —
65-байтный, 86–87 символов base64url. Его нет ни в одном файле репозитория
(проверено: `grep -rEo "[A-Za-z0-9_-]{86,87}"` по `.md/.json/.sh/.yml` — только
шум из `.android-sdk`; в `apikeys.json` обе ячейки `production.push.VAPID_*`
пусты; `instruktion_get_keys.md:32` содержит то же 43-символьное значение, что и
`.env.production`, то есть источник реестра ключей тоже невалиден). Публичную
часть нельзя восстановить из приватного ключа — поэтому вопрос именно про
наличие сохранённого значения (где генерили 07.09.2026, есть ли второй ключ).

**Как проверить без раскрытия секрета** (на сервере, выводит только длину):

```bash
node -e 'const t=require("fs").readFileSync("/data/balloo/repo/docker/prod/.env.production","utf8");for(const k of ["VAPID_PUBLIC_KEY","VAPID_PRIVATE_KEY"]){const m=t.match(new RegExp("^"+k+"=\"?([^\"]*)\"?","m"));console.log(k+" bytes="+(m?Buffer.from(m[1],"base64url").length:"нет"))}'
```

Ожидание после вашего решения: `VAPID_PUBLIC_KEY bytes=65`.

**Смежный пробел (это моя работа, не ваша).** Даже с валидной парой браузер не
подпишется: `VITE_VAPID_PUBLIC_KEY` не пробрасывается в docker-сборку веба
(`grep -c VAPID docker/Dockerfile.web` → **0**), а `packages/web/src/service-worker-registration.ts:202`
читает именно его. Отдельная задача — сделаю после появления валидного значения
(тот же путь, что чинили для Метрики в тик. 1793270207).

**Чего я НЕ предлагаю:** ротацию секретов — пункт 1 раздела «Решения владельца»
(`AGENTS.md`) остаётся в силе. Здесь речь только о том, что записанное значение
не является валидным VAPID-ключом и browser push с ним работать не может.

**Блокирует:** browser-push-уведомления (не работают с 07.09.2026 — инициализация
ни разу не проходила). Деплой, переписку, вход и мобильный in-app push — нет.
