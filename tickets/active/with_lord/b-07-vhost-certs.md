## Цель

Поднять 6 новых сайтов поддоменов на сервере: nginx-vhost'ы, TLS, compose-сервисы,
CORS-список, env для desktop/mobile.

## Жёсткие рамки (из `AGENTS.md`, не обсуждаются)

- **SSH-доступа к серверу у ассистента нет.** Формат работы: батч (≤15 строк) →
  вывод владельца → анализ → следующий батч.
- **Запрещено:** `docker compose down`, `rm`, `network prune` (сеть `balloo-net`
  со шлюзом `172.19.0.1` = `SMTP_HOST` postfix-релея, пересоздание молча ломает
  почту), `up -d --build` на весь стек, `systemctl restart docker`,
  `git clean -fd`, `git reset --hard`, `docker builder prune -a`.
- Перед любой записью — тег откатной точки образа.
- `systemctl restart balloo` деплоем не является (юнит зёт deploy-скрипт без `--build`).

## Что нужно сделать

1. **Выбор архитектуры в начале тикета (решение владельца, записать в `docs/01`):**
   отдельный контейнер + порт на каждый поддомен **или** один nginx с несколькими
   `server_name`. От этого зависит объём compose-правок.
2. Батчи vhost'ов по образцу существующего
   `/etc/nginx/sites-enabled/balloo-docker.conf` и `enable-probes.sh`:
   `features`, `admin`, `command`, `download`, `history`, `docs`, `blog` —
   + certbot по одному на домен, dry-run перед применением.
3. compose: новые сервисы (web-features / web-admin / web-command / web-info)
   **без пересоздания** `postgres`, `redis`, `minio`, `server`.
4. `CORS_ORIGIN` — полный список новых origin'ов (формат §3.3 мультитикета:
   список через запятую, `connectSrc` в `security.ts` умеет разбирать).
5. env desktop/mobile → `api.balloo.su`.
6. Закоммитить готовые оптимизации `Dockerfile` (лежат в репо, ждут коммита —
   запись мультитикета §5; проверить актуальность `git status` перед коммитом).
7. **Только после приёмки:** отдельный nginx-батч на удаление compat-прокси
   `/api/` и `/ws/` с `balloo.su` — когда подтверждено, что desktop/mobile обновлены.

## Критерии готовности

- `docker compose ps` — все сервисы Up, `restart_count=0`, `postgres`/`redis`/`minio`
  **не** перезапускались (аптайм как в батче C).
- Каждый новый поддомен отвечает HTTPS с валидным сертификатом (вывод `curl -I`).
- Откат каждого батча проверен dry-run'ом.
- Почта не сломана: сеть `balloo-net` не пересоздавалась (проверка `docker network inspect`).
- Каждое утверждение о проде подкреплено выводом сервера; без него статус — «не подтверждено».
