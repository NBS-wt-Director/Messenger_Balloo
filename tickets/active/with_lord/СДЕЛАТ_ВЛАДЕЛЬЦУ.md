## 15. Медиа с MinIO — `cdn.balloo.su` не настроен в nginx (В-99)

**Зависимость:** нет. **Сверено с кодом 02.10.2026 17:53 МСК** (не по памяти).

**Статус:** ⬜ **ТРЕБУЕТ ДЕЙСТВИЙ ВАС** — нужна правка nginx и DNS на сервере, у меня туда доступа нет.

### Факты из кода

| Что | Значение | Где |
|-----|----------|-----|
| Запись в MinIO | работает | `uploadService.ts:73` `createMinIOClient()`, клиент `new client.Client({endPoint: env.MINIO_ENDPOINT, port: Number(env.MINIO_PORT), ...})` |
| `MINIO_ENDPOINT` / `PORT` / `SSL` / `BUCKET` | `minio` / `9000` / `false` / `balloo-media` | `docker/prod/.env.production:28-31` |
| **Отдача URL браузеру** | `cdnUrl()` = `${CDN_BASE_URL}/${path}` | `uploadService.ts:66` |
| Боевой `CDN_BASE_URL` | **`https://cdn.balloo.su`** | `.env.production:129`, `docker-compose.prod.yml:28`, `docker-compose.yml:109` |
| Fallback (без env) | `http://localhost:9000/balloo-media` | `config/paths.ts:17` |
| Порты MinIO в проде | `9000:9000` **и** `9001:9001` опубликованы | `docker-compose.prod.yml:96-97` |

### Диагноз (В-99)

`CDN_BASE_URL` ведёт на **`cdn.balloo.su`**, но **`cdn.balloo.su` отсутствует в `server_name` ни в одном блоке nginx** — в `docker/prod/nginx-production.conf` перечислены только `balloo.su app api staging admin docs download features history command blog` (строки 99-103 и 120-124). Блока для `cdn.balloo.su` нет.

Запрос к `https://cdn.balloo.su/<файл>` не совпадёт ни с одним `server_name` → nginx отдаст **дефолтный** первый сервер (блок `balloo.su`) → SPA-заглушку вместо файла. **Медиа загрузится в MinIO, но не отобразится.**

Публикация порта `9000:9000` в проде проблему не решает: `CDN_BASE_URL` на него не указывает.

При этом `cdn.balloo.su` **уже заложен** в инфраструктуру — есть в таблице DNS (`instruction_for_deploy_on_server_and_start_project_For_users.md:98`) и в команде certbot (там же, строка 200). Не хватает только серверного блока nginx.

### Что сделать (4 шага)

1. **DNS:** проверить, что `cdn.balloo.su` имеет A-запись на IP сервера (уже предписано инструкцией).
2. **Блок nginx** для `cdn.balloo.su` — проксировать на MinIO, путь bucket подставляется:
   ```nginx
   server {
     listen 443 ssl http2;
     server_name cdn.balloo.su;
     ssl_certificate     /etc/nginx/ssl/balloo.su/fullchain.pem;
     ssl_certificate_key /etc/nginx/ssl/balloo.su/privkey.pem;
     location / {
       proxy_pass http://minio:9000/balloo-media/;
       proxy_set_header Host $host;
       add_header Cache-Control "public, max-age=31536000, immutable";
     }
   }
   ```
   Сертификат balloo.su должен включать `cdn.balloo.su` как SAN (certbot-команда в инструкции его уже перечисляет). Затем `nginx -t && systemctl reload nginx`.
   > Если nginx крутится **вне** docker-сети (`minio` не разрешится) — заменить `http://minio:9000/` на `http://127.0.0.1:9000/`, порт опубликован.
3. **Анонимное чтение bucket** (иначе `403 AccessDenied`): в консоли `:9001` → bucket `balloo-media` → Access Policy → `public`, либо `mc anonymous set download local/balloo-media`.
4. **Тест:** загрузить аватар в UI → взять `url` из ответа API → открыть в браузере. Ожидание: **HTTP 200 + `image/*`**, не HTML-заглушка и не 403.

### Стоп-факторы

- Отдался HTML (SPA) вместо картинки → блок из шага 2 не подключён или DNS не ведёт на сервер.
- `403 AccessDenied` → шаг 3 (политика bucket).
- `502 Bad Gateway` → `proxy_pass` не достает MinIO (шаг 2, примечание про сеть).
