## Что нужно сделать

1. **Переснять покрытие свежим прогоном** (артефакты от 07.09 устарели):
   ```bash
   pnpm --filter @balloo/web test -- --coverage
   pnpm --filter @balloo/server test -- --coverage
   ```
   Имена пакетов проверить в `packages/*/package.json`.
2. **Найти провалы:** из `coverage-summary.json` — файлы с 0% покрытия, отсортировать
   по числу строк (самые большие непокрытые модули дают наибольший прирост).
3. **Поставить цель честно.** 80% по statements для фронта целиком — это недели
   работы. Практичный вариант: **80% по statements для `server`** (логика, деньги,
   безопасность) и **70% для `web`**, плюс обязательное 100% покрытие:
   аутентификация, платёжный модуль, обработка токенов, middleware.
4. **Писать тесты пачками по модулю**, каждый коммит = один модуль + зелёной
   прогон. Не «один большой коммит тестов».
5. **Shared:** завестиcoverage-конфиг (отчёта нет вообще).
6. **Порог в конфиге:** после выхода на целевые цифры зафиксировать `thresholds`
   в `vitest.config.ts`, чтобы деградация падала в CI.

## Критерии готовности

- Свежие отчёты покрытия лежат в `packages/*/coverage/`, даты = дата закрытия.
- Целевые проценты достигнуты и **доказаны цифрой** из `coverage-summary.json`,
  не «на глаз».
- Критический контур (auth/payments/middleware) покрыт полностью — по файлам видно 100%.
- Порог в конфиге = фактическое покрытие (не желаемое), иначе CI будет врать.
