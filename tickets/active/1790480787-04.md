## Цель

Поднять `features.balloo.su` как отдельный фронтенд-пакет на `@balloo/ui`
и доработать бэкенд под анонимные/неанонимные фич-предложения.

| Предмет | Факт |

| Макеты | `mockups/features-balloo-su/` — 6 экранов, эталон |

## Что нужно сделать

**Фронтенд (новый пакет):**
1. `packages/web-features` на образце `packages/web`: Vite + React + `@balloo/ui`
   (Topbar/Footer/ThemeProvider/I18nProvider — шапка/подвал не дублировать).
2. `VITE_API_URL=https://api.balloo.su` (клиент сам дописывает `/api/...`);
   dev — `http://localhost:3100`.
3. Экраны по макетам: список, карточка, создание, голосование, «мои предложения»
   (история + статусы).
4. Вход через balloo.su — сессия по cookie на домене `.balloo.su` (§3.2 мультитикета);
   анонимный просмотр и голосование без входа.
5. `docker/Dockerfile.features` по образцу `Dockerfile.web` (не забыть COPY
   `packages/ui/` и `packages/shared/` — иначе `--frozen-lockfile` падает).

**Бэкенд:**
6. Миграция `isAnonymous Boolean @default(true)` на `FeatureRequest`
   (Prisma-миграция, не `db push`; колонки в PostgreSQL — `camelCase` в кавычках,
   учтено в `docker/prod/p33-clean-e2e-account.sh`).
7. При создании — выбор автора; в голосовалке неанонимные показывать
   привлекательно (аватар + имя + бейдж).
8. **В админке отличия анонимности не показывать никак** (прямое требование).

## Критерии готовности

- Пакет существует, собирается, `tsc --noEmit` чисто.
- Анонимный вход/голос работают без сессии; вход через balloo.su даёт «свои предложения» со статусами.
- Неанонимное предложение отображается с аватаром/именем/бейджем.
- В админке анонимные и неанонимные выглядят одинаково — скриншоты обоих случаев.
- Тесты бэкенда зелёные; `FeatureVote` не сломан (существующие тесты проходят).

## Связь

Без `-07` (vhost + certbot + compose) сайт доступен только локально. Прод-статус —
«не подтверждено» до вывода сервера.
