### Детальный разбор реальных проблем

#### 1. Ошибка 404 при загрузке EmployeesScreen в админке

**Что:** `EmployeesScreen` (web-admin) делает `GET /api/admin/employees`, но такого эндпоинта нет в `admin.ts`.
**Факты:**
- `admin.ts` содержит 21 endpoint (users, bans, reports, announcements, feature-flags, versions, metrics, audit-logs, support/tickets, groups/media-requests)
- `EmployeesScreen.tsx` делает `api.get<any>('/api/admin/employees')`
- `EmployeesScreen.tsx` — принятый MVP1 экран (1.1.14)
- Prisma модель `Employee` отсутствует в schema.prisma

**Решение:**
- **Я:** создаю `prisma.Employee` модель (поля из data_schema.json: id, name, position, departmentId, email, phone, isActive, createdAt, updatedAt) + эндпоинт `GET /api/admin/employees` в adminController + admin.ts
- **Владелец:** ничего не нужно (если нет специфических требований к данным сотрудников)
- **Время:** ~2 часа
- **Риск:** низкий — данные сотрудников не критичны для MVP1

#### 2. Нет WS call signaling (звонки)

**Что:** Звонки (1_01_10, 1_01_11) входят в MVP1. REST API есть (history, create, end), но WebSocket-сигналинг отсутствует.
**Факты:**
- WS events в коде: message.send, message.read, typing.start/stop, presence.update, reaction.add/remove, story.view (8 событий)
- WS events в spec: те же 8
- Отсутствуют: call.start, call.answer, call.decline, call.end, call.negotiation, call.hangup
- UI есть: CallsScreen, ActiveCallScreen
- REST endpoints: POST /api/calls (initiate), POST /api/calls/:id/end, GET /api/calls (history)
- Prisma: Call, CallParticipant модели есть

**Решение:**
- **Я:** добавляю 4 WS event handler'а в ws/handlers.ts (call.start, call.answer, call.decline, call.end) + типизацию в ws/types.ts
- **Владелец:** ничего не нужно
- **Время:** ~3–4 часа
- **Риск:** средний — WebRTC negotiation (offer/answer/ICE) требует peerconnection.js на клиенте, это часть UI-логики

#### 3. 52 таблицы в data_schema.json без Prisma-моделей

**Что:** data_schema.json описывает 101 таблицу, Prisma — 77 моделей. Расхождение 24 модели (не 52, я ошибся в первой оценке — многие Prisma-модели имеют @@map, который совпадает с именами таблиц).
**Факты:**
- Из 24 расходящихся: 13 — алиасы (ChatMember↔UserChat, Ban↔UserBan, Invite↔InviteLink, TwoFASecret↔User2FASecret, Attachment↔MessageAttachment)
- 11 genuinely missing: employees, department_members, hr_requests, interviews, candidate_match_scores, interview_decisions, interview_notes, interview_ratings, time_off_requests, meetings, meeting_protocols — все принадлежат Command (у_03), вне MVP1
- donate_tiers → DonationTier ✅ (@@map("donation_tiers"))
- versions → ServiceVersion ✅ (@@map("service_versions"))
- service_status_incidents/snapshots → ServiceMetric ✅ (для admin "Метрики")

**Решение:**
- **Я:** ничего не нужно (все отсутствующие таблицы — Command, вне MVP1)
- **Владелец:** подтвердить, что Command вне MVP1
- **Время:** 0 минут
- **Риск:** нет
