# Тикет 1795152410 — Кэш фронта: версионировать CACHE_NAME и запретить кэш index.html

**Создан:** 20.11.2026 10:20 (unix 1795152410)
**Статус:** в работе
**Источник запроса:** разбор «у некоторых узлов сохранилось старое меню»
(тикет `with_lord/1795152409-пересборка-всего-и-ключи.md`, Часть C)

## Цель

Устранить механизм, из-за которого после деплоя у пользователя остаётся старая
версия приложения (и, как следствие, старое левое меню), до ручного сброса
Service Worker.

## Диагноз (доказано чтением файлов и `curl`)

1. `packages/web/public/sw.js:3` — `const CACHE_NAME = 'balloo-v1';`
   Имя кэша **не меняется** между релизами, а `activate` удаляет только кэши с
   **другими** именами (`sw.js:126-135`). Значит `balloo-v1` живёт между деплоями.
2. `sw.js:161-177` — статика (`cacheFirst`) отдаётся **из кэша без обращения к
   сети**; новый файл подтянется только если изменился его URL (хэш Vite это
   обеспечивает для `/assets/*`, но **не** для `sw.js` и прочих некэшированных).
3. `docker/nginx.conf:63-67` — для `location /` нет `Cache-Control` для
   `index.html`. `curl -sI https://balloo.su/` → заголовка `Cache-Control` нет,
   есть `ETag`/`Last-Modified` → браузер применяет эвристическую свежесть.

## Подзадачи

- [ ] 1. `sw.js`: сделать `CACHE_NAME` версионируемым. Вариант без сборки —
      подставлять версию в имя (например, `balloo-v2`), поднимать при релизе;
      предпочтительно — генерировать из хэша сборки (плагин/скрипт при `vite build`).
      Проверка: `grep -n CACHE_NAME packages/web/public/sw.js` показывает новую схему.
- [ ] 2. `docker/nginx.conf`: для `index.html` и `sw.js` — `Cache-Control: no-cache`
      (перепроверка ETag при каждом запросе); для `/assets/` — `public, max-age=31536000, immutable`.
      Проверка: `curl -sI https://balloo.su/` содержит `Cache-Control: no-cache`;
      `curl -sI https://balloo.su/assets/index-*.js` содержит `immutable`.
- [ ] 3. Сборка и тесты: `pnpm --filter @balloo/web build`, `pnpm --filter @balloo/web test`.
- [ ] 4. Локальная проверка живым браузером: после правки старый SW (`balloo-v1`)
      удаляется на `activate`, новая версия подхватывается без ручного сброса.

## Критерии готовности

- [ ] `CACHE_NAME` меняется при релизе (не константа `-v1`)
- [ ] `index.html`/`sw.js` не кэшируются браузером надолго, ассеты — `immutable`
- [ ] Сборка и тесты зелёные (вывод команд в «Результат»)
- [ ] Живой браузер подтверждает обновление без ручного Unregister

## Проблемы и решения

- Нельзя просто поставить `no-cache` на всё: хешированные ассеты выгодно кэшировать
  надолго, иначе каждая загрузка тянет мегабайты. Поэтому — раздельные правила.
- `sw.js` раздаётся из `public/` без хэша; при `immutable` его нельзя будет
  обновить → для него обязателен `no-cache`.
