## Что требуется

### MVP1

**1. Направление движения.** Левый тикер бежит от левого края к центру, правый — от правого края к центру (сходятся в центре). Сейчас оба бегут слева направо.

**2. Кодирование азбукой Морзе.** Тикер воспроизводит последовательность **точек и тире** (не одинаковых точек), кодирующую текст:
- короткий импульс = точка (`.`), длинный = тире (`-`);
- между символами — пауза, между словами — большая пауза;
- текст в тикере — не читаемый буквами, а морзе-паттерном.

**3. Режим «нет уведомлений» (по умолчанию).**
- Левый тикер: слоган **«переверни общение!»** в морзе.
- Правый тикер: **часовой пояс + предполагаемый город** пользователя в морзе (например «UTC+5 Екатеринбург»). Определяется из `Intl.DateTimeFormat().resolvedOptions().timeZone` на клиенте (без IP-геолокации в MVP1).

**4. Режим «есть активное уведомление».**
- Левый тикер: **источник** — тип (чат / группа / контакт / приглашение / вызов) в морзе.
- Правый тикер: **тело** уведомления (превью) в морзе.
- Уведомление приоритетнее слогана/города; после прочтения (или таймаута) — возврат к режиму «нет уведомлений».

**5. Уведомление об обновлении.** При планировании обновления всем **онлайн** пользователям через это же поле показывается сообщение («Обновление в HH:MM», левый = «Обновление», правый = время/суть).

### MVP2

**6. Экстренные оповещения о ЧС** — красный цвет тикера:
- левый тикер: район **фактического** местонахождения;
- правый тикер: **предполагаемое реальное** местонахождение.

### MVP4

**7. Вычисление реального местоположения при VPN.** По группам/сообщениям/чатам определяем предполагаемое реальное местоположение пользователя, если замечен включённый VPN. **Никому не сообщаем** — используется только для адресной доставки сообщений/оповещений.
