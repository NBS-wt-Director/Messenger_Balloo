## 1. Что живёт в `active/`

| Тип файла | Пример | Правило |
|---|---|---|
| Тикет-задача | `<unix>.md`, `mvp1-04-<коротко>.md` | одна задача = один файл, формат — `tickets/ПРОТОКОЛ.md` §3 |
| Этот протокол | `ПРОТОКОЛ.md` | не задача, в очередь не входит |
| Подпапка владельцу | `with_lord/` | свои три файла, свой протокол (`with_lord/ПРОТОКОЛ.md`) |

**Служебные выгрузки** (`_*`, `~*`, `.txt`) здесь не складываются: при запуске
«.» и «Продолжай» они исключены из чтения, но плодят видимость задач.

## 3. Шаг «Приборка» — один проход перед выполнением тикетов

Каждый файл в `tickets/active/` (рекурсивно, без `with_lord/`, без `_*` и `~*`)
проверить на четыре признака и разложить:

| Признак | Куда |
|---------|------|
| задача **выполнена** (есть доказательство: команда/путь/diff) | `tickets/Done/<ГГГГ-ММ-ДД>/<unix>.md` |
| задача **не выполнена** и делима дальше | разбить на минимальные, сохранить в `active/`, исходный файл удалить |
| задачу могу сделать **только владелец** (приёмка, сервер, данные, ключи, решения) | перенести формулировку в `tickets/active/with_lord/СДЕЛАТЬ_ВЛАДЕЛЬЦУ.md`, файл из `active/` удалить |
| файл **проверен и полностью обработан** по этой схеме | `tickets/archive/<ГГГГ-ММ-ДД>/<unix>.md` |

Запрещено: менять содержимое таблиц владельца; править `AGENTS.md`; что-либо
удалять без переноса в Done/archive.

## 4. Шаг «Проверка путей перед записью тикета» (внесено 09.10.2026)

Причина: в `active/` оказался тикет `1790443200` с разбором **другого проекта**
(пути `server/gateway/src/plugins/...`, домены `breezka.ru`). Ни одного такого
пути в balloo нет — вывод тикета маскировал реальную правку. Файл удалён
09.10.2026 по решению владельца, в git не попадал.

Правило перед записью любого тикета или правки по чужому разбору:

1. Каждый путь из формулировки проверить existence: `ls <путь>` или
   `git ls-files <путь>`.
2. Каждое имя переменной/функции/литерал проверить: `grep -rn "<имя>" packages/`.
3. Если путь относится не к этому монорепо (нет в `git ls-files`) — тикет **не
   создавать**, а сказать владельцу, в какой репозиторий он относится.
4. Ссылка в тикете допускается только `путь:строка`, где номер строки подтверждён
   `grep -n`/`sed -n` и не превышает `wc -l` файла.

**Допилено 15.10.2026:** предпосылки («ничего не вызвано», «файл пустой») тоже
проверяются grep'ом. Пример того дня: запись В-118 «из экранов не вызывается»
оказалась неверной — `TasksScreen.tsx` вызывает методы `/api/tasks`; тикет
`1792062709` заведён с проверенным составом.

## 5. Шаг «Один писатель в tickets/» (внесено 09.10.2026)

Причина: 09.10.2026 в дереве одновременно работали две сессии — пять сдвигов
HEAD за одну сессию чтения, четыре правки отбиты как «file modified since read».

1. Правит `tickets/` одна сессия. Если владелец держит открытой вторую — сказать
   ей «стоп» до начала правок.
2. Перед каждой записью: `git rev-parse --short HEAD` сверить с запомненным в начале
   прохода. Отличается — перечитать файл, план прохода пересобрать.
3. Не держать «в голове» список файлов `active/`: перед раскладкой снимать его
   заново (`ls -1 tickets/active/`).
4. Прочитал файл, получил пустой ответ — это **не** «файл пустой». Проверить
   `wc -c <файл>` и `git ls-files <файл>`; содержимое по описанию из соседних
   файлов не восстанавливать.
