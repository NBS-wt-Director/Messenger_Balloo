**UNIX-в-имени = 1790000000 — маркер порядка, не дата создания. Файл читается ПЕРВЫМ
по сортировке п.5 «Продолжай» и задаёт правила для остальных файлов.**
Записан по указанию владельца 08.10.2026 (Ksyusha, сессия приборки).

## Шаг 0. Приборка (один проход, перед выполнением тикетов)

Каждый файл в `tickets/active/` (рекурсивно, без `with_lord/`, без `_*` и `~*`)
проверить на четыре признака и разложить:

| Признак | Куда |
|---------|------|
| задача **выполнена** (есть доказательство: команда/путь/diff) | `tickets/Done/<ГГГГ-ММ-ДД>/<unix>.md` |
| задача **не выполнена** и делима дальше | разбить на минимальные, сохранить в `active/` как `а-[номер]-<кратко>.md`, исходный файл удалить |
| задачу могу сделать **только владелец** (приёмка, сервер, данные, ключи, решения) | перенести формулировку в `tickets/active/with_lord/СДЕЛАТ_ВЛАДЕЛЬЦУ.md`, файл из `active/` удалить |
| файл **проверен и полностью обработан** по этой схеме | `tickets/archive/<ГГГГ-ММ-ДД>/<unix>.md` |

Запрещено: менять содержимое таблиц владельца; править `AGENTS.md`; что-либо
удалять без переноса в Done/archive.

## Шаг 0bis. Проверка путей перед записью тикета (внесено 09.10.2026)

Причина: в `tickets/active/` оказался тикет `1790443200` с разбором **другого
проекта** (пути `server/gateway/src/plugins/...`, домены `breezka.ru`, скрипт
`server/gateway/package.json`). Ни одного такого пути в balloo нет — вывод тикета
(«CORS чинить не надо») был неприменим к нам и маскировал реальную правку.
Файл удалён 09.10.2026 по решению владельца («не наш — не нужен»), в git он не
попадал (`git log --all -- <файл>` → 0 коммитов).

Правило перед записью любого тикета или правки по чужому разбору:

1. Каждый путь из формулировки проверить existence: `ls <путь>` или
   `git ls-files <путь>`.
2. Каждое имя переменной/функции/литерал проверить: `grep -rn "<имя>" packages/`.
3. Если путь относится не к этому монорепо (нет в `git ls-files`) — тикет **не
   создавать**, а сказать владельцу, в какой репозиторий он относится.
4. Ссылка в тикете допускается только `путь:строка`, где номер строки подтверждён
   `grep -n`/`sed -n` и не превышает `wc -l` файла.

## Шаг 0quater. Один писатель в tickets/ (внесено 09.10.2026)

Причина: 09.10.2026 в дереве одновременно работали две сессии. Замер:
`git reflog -5` показал пять сдвигов HEAD за одну сессию чтения
(`46696ec → 9d59bdf → 42e6fa5 → a48c69d → 5155ecc`), последний — чужой коммит
`docs(tickets): приборка active`. Четыре мои правки в `active/` отбиты инструментом
как «file modified since read»; вывод «очереди `а-NN` нет» оказался верным только
для состояния до чужого коммита.

Правило:

1. Правит `tickets/` одна сессия. Если владелец держит открытой вторую — сказать
   ей «стоп» до начала правок.
2. Перед каждой записью: `git rev-parse --short HEAD` сверить с запомненным в начале
   прохода. Отличается — перечитать файл, план прохода пересобрать.
3. Не держать «в голове» список файлов `active/`: перед раскладкой снимать его
   заново (`ls -1 tickets/active/`).
4. Прочитал файл, получил пустой ответ — это **не** «файл пустой». Проверить
   `wc -c <файл>` и `git ls-files <файл>`; содержимое по описанию из соседних
   файлов не восстанавливать.

Выполнить всю очередь `а-NN` по одному («Дальше»), затем вывести отчёт:

```

```

инфраструктура). Числа обновлять только по факту сборки/скриншотов, на глаз не менять.
