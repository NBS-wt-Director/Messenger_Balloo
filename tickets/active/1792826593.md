**Создан:** 24.10.2026 12:23 (unix 1792826593)
**Статус:** в работе
**Источник запроса:** этап A деплоя P38 (1792812416) — `pnpm test` красный на полном
прогоне серверных тестов при зелёных наборах в изоляции.

## Цель

Сделать `pnpm test` детерминированно зелёным на этой машине (16 ядер), не навредив CI.

## Диагноз (снято прогонами 24.10.2026)

- Полный прогон `pnpm --filter @balloo/server test`: 7–11 наборов падают,
  **состав падающих меняется от прогона к прогону**; те же наборы по отдельности —
  зелёные (проверено: 7 наборов вместе → 126/126 PASS).
- Тексты ошибок: `FATAL: remaining connection slots are reserved for roles with
  the SUPERUSER attribute`, `Registration failed: 500`, `● Timeout` — всё следствия
  исчерпания слотов Postgres.
- Причина: `max_connections=100` (замер `SHOW max_connections`); Prisma 5 по
  умолчанию открывает пул `cores*2+1` = **33** соединения **на каждый клиент**, а
  каждый модуль сервера создаёт свой `new PrismaClient()` (grep по `src/`).
  На 16-ядерной машине полный `--runInBand` прогон выжигает 100 слотов.
  CI-раннеры GitHub 2–4 ядра (пул 5–9) — там проходит «по удачному стечению».

- Слоты Postgres кончались только в середине прогона → наружу выходили 500-ки и
  30-секундные таймауты в наборах, не связанных с БД текстом тестов. Это маскировало
  диагноз; снимался перебором: изоляция наборов → зелёные, полный прогон → красный,
  `pg_stat_activity` → слоты.
