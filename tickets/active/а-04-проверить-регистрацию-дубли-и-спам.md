# а-04: проверка регистрации — дубли, спам, скорость

**Что смотрим:** `/api/auth/register` (`routes/auth.ts:40-91`).

## Чек-лист

1. Дубли: `email.toLowerCase().trim()` (строка 57) + уникальный индекс в `schema.prisma`
   (ищем `@@unique([email])`) — прикладной `findUnique` гонится в race при параллели,
   спасает только БД-индекс. Проверить обработку P2002.
2. Нормализация email: `trim().toLowerCase()` — есть; Unicode/`.`/`+` не нормализуем
   (решение владельца по этой ручке есть — не расширяем).
3. Подтверждение email: `verification_tokens` создаётся (строка 66), письмо уходит?
   Проверить `services/verification.ts` и `EmailType.VERIFY_EMAIL`.
4. Спам-защита: только rate limit `app.ts:169`? Капча/проверка на вход пароля — нет.
   Параллельно с `исправить-bcrypt-cost-12.md`.
5. Автологин после регистрации (строки 79-81) — ок, но cookie ставят `maxAge` 15 мин /
   30 суток; проверить, что после `/register` без подтверждения доступны только
   `whoami`+`verify` (см. `а-13`).
6. Логирование: в `logger.info('user registered')` (строка 84) не попадает email/пароль.
