# исправить: отзыв refresh-токенов (критично, объёмная)

**Слой:** 2 (сессии). **Найдено:** 08.10.2026, аудит по сессии.

## Что найдено

- `packages/server/src/services/auth.ts:27-31` — refresh HMAC, срок 30 суток, **без ID и без хранилища**.
- `packages/server/src/routes/auth.ts:94-136` (`/refresh`) — подпись + срок, ничего больше.
- `packages/server/src/routes/auth.ts:139-145` (`/logout`) — только清 cookie.

Итог: украденный refresh живёт 30 суток, отозвать нельзя ни пользователю, ни админу,
ни при смене пароля. Выход с устройства сессию не прекращает.

## Что сделать

1. Таблица `refresh_tokens`: `id (jti)`, `user_id`, `family_id`, `expires_at`,
   `rotated_at`, `user_agent`, `ip`, `revoked_at`.
2. `/refresh`: проверить подпись и срок → найти `jti` → если `revoked_at` не NULL или
   `jti` уже повёрнут (reuse) → отозвать всю `family_id` (защита от клонирования), 401.
3. `/logout`: отозвать текущий `jti` + family.
4. Смена пароля / вход с нового устройства → отзыв по `family_id`.
5. Миграция + индекс по `user_id, expires_at`.

## Как проверить

Интеграционка: refresh → logout → повторный refresh = 401; reuse повёрнутого токена
= 401 и отзыв family; тест миграции на тестовой БД.

## Связь с решениями владельца

Не противоречит. Схема БД правится — owner-решений по этой таблице нет.

## Результат (11.10.2026) — реализовано, таблица БД не нужна

Тикет написан 08.10 по устаревшему пути `services/auth.ts` (файла нет; актуальный
`services/authService.ts`). Критическая цель — «украденный refresh нельзя отозвать,
выход с устройства сессию не прекращает» — **уже закрыта** реализацией на Redis
(коммиты 05f2480 и ранее), а не проектом таблицы `refresh_tokens`. Фактическое
состояние `authService.ts`:

- refresh-токен несёт `jti` (`crypto.randomUUID()`, строки 88-89) — «без ID» из
  описания тикета неактуально;
- **ротация**: при каждом refresh старый `jti` уходит в Redis-блоклист
  `revoked-jti:<jti>` с TTL = срок жизни токена (525-526) → повторное использование
  повёрнутого токена отклоняется на входе (499-503, `401 Refresh токен отозван`);
- **`/logout`**: отзыв текущего `jti` (543-548); `allDevices`/`/logout-all` →
  `revokeAllSessions(userId)` (555, 295) — метка по `iat` гасит ВСЕ токены пользователя
  до этой метки, включая refresh (проверка `isSessionRevoked` в refreshTokens, 507);
- **смена/сброс пароля** → `revokeAllSessions` (693) — старый вход переживает
  компрометацию только до ближайшего refresh, теперь гасится сразу.

Отличие от проекта тикета: вместо `family_id` в БД — связка «per-jti блоклист +
метка отзыва по iat». Защита от клонирования (reuse) держится на блоклисте
повёрнутого jti, отзыв всех сессий — на iat-метке. Дублирующую таблицу не заводим:
это был бы рефакторинг работающего, покрытого тестами кода без нового функционала
(AGENTS §главное — продукт, не рефакторинг ради рефакторинга).
