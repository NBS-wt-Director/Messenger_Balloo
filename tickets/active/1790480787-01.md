# Тикет 1790480787-01 — P38-0: гостя сбрасывает с публичных страниц на /login

## Симптом (прод, доказан)

`https://balloo.su/#/blog`, `/#/`, `/#/privacy` у гостя заканчиваются
`hash=/login`. В прогоне `scripts/p37-prod-check.cjs` две строки помечены
`REDIRECT->/login` — это `/` и `/blog`.

## Причина (снимок сетевых запросов, `scripts/p38-prod-redirect-probe.cjs`)

1. `GET https://api.balloo.su/api/users/me` → **401** (гость);
2. `POST /api/auth/refresh-cookie` → **400**, потому что refresh-куки нет вообще
   (`packages/server/src/controllers/authController.ts:206-234`: `if (!refreshToken) → 400`);
3. клиент в ветке «refresh не ок» делает `window.location.hash = '#/login'`
   (`packages/web/src/services/api.ts:64-73`);
4. `AuthProvider` вызывает `api.getMe()` при монтировании на **любом** маршруте,
   включая публичные (`packages/web/src/components/providers/AuthProvider.tsx:54-66`).

## Суть фикса

Различать два состояния:

| Ситуация | Ответ refresh | Что делать |
|---|---|---|
| сессии нет вообще | **400** | URL **не трогать**; решение о входе принимает `ProtectedRoute` (`packages/web/src/router/index.tsx:140-176`) |
| сессия протухла | **401** | редирект на `/#/login` — текущее поведение оставить |
