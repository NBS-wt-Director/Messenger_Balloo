## Что сделает владелец в момент триггера (без этого задача стоит)

1. Зарегистрировать магазин на `yookassa.ru`. Статус владельца (ИП /
   самозанятый / физлицо) — **уточнить тогда же**, от него доступны способы
   приёма.
2. `shopId` + `secretKey` — внести в админку или в живой `.env` сервера.
   **В тикеты и в `AGENTS.md` значения не записывать** (см. запрет в
   `1790443419-bezopasnost-i-sekrety`).
3. Кассовое обеспечение для платежей физлиц: ШИФТ + ОФД.
4. Тестовая карта песочницы — для проверки на сервере.

## Порядок работ при наступлении триггера

1. Прочитать `createDonation` и `handleWebhook` целиком — подтвердить, что
   статус оплаты ставится из вебхуша, а не вручную (сейчас не читано целиком).
2. Песочница: тестовая карта → платёж → вебхук на нашем сервере → статус в
   БД → запись видна в админке.
3. Проверить доступность `/api/payments/webhook/yookassa` снаружи (у у
   прод-домена может потребоваться белый список IP ЮKassa).
4. Только после зелёной песочницы — боевые ключи и реальный платёж
   минимального тарифа с последующим возвратом.
