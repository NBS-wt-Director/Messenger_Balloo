## Цель

Четыре сайта (download, history, docs, blog) отдельными сборками на `@balloo/ui`,
чтобы шапка/подвал/темы/языки не переписывались четыре раза.

## Фактическое состояние (2026-09-27)

| Предмет | Факт |
|---|---|
| Пакеты `web-download`, `web-history`, `web-docs`, `web-blog` | **не существуют** (`ls -d packages/web-*` пусто) |
| Экраны сейчас | живут внутри `packages/web`: `DownloadScreen`, `HistoryScreen`, `DocsScreen`, `screens/blog-landing/*` (6 экранов, подвалы дописаны в P37, коммит `97d7077`) |
| Макеты | `mockups/download-balloo-su/` (2), `history-balloo-su/` (3–4), `docs-balloo-su/` (1), `blog-balloo-su/` (6) — эталон |
| Общий UI | `@balloo/ui` готов и используется web — переиспользовать, не дублировать |

## Что нужно сделать

1. Четыре пакета-сборки. Для download/history/docs допустима **статическая**
   сборка (без роутера состояния), для blog — данные через существующий API,
   своей БД не заводить.
2. `web-docs` — Swagger UI по OpenAPI бэкенда (вместо самописной страницы),
   если OpenAPI-спека отдаётся; если нет — сначала сгенерировать спеку,
   это отдельная подзадача.
3. Шапка/подвал/переключатели — только из `@balloo/ui` (Topbar, Footer,
   ThemeProvider, I18nProvider). i18n минимум: шапка, подвал, заголовки.
4. `VITE_API_URL=https://api.balloo.su` там, где есть обращения к API (blog).
5. Контент 1:1 с макетами.
6. Инфраструктура (vhost/certbot/compose) — тикет `-07`.

## Критерии готовности

- Четыре пакета собираются (`tsc --noEmit` чисто в каждом).
- Каждый сайт открывается локально, контент = макет (скриншоты рядом с макетом).
- Темы (dark/light/russian) и языки работают на всех четырёх.
- Blog получает данные из API, собственной БД нет (в `schema.prisma` новых таблиц блога не появилось).
- В `packages/web` не осталось мёртвых копий перенесённых экранов.
