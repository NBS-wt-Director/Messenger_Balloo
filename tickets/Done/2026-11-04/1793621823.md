## Проблемы и решения

- **Флак `pnpm test` — причина найдена прогоном, а не догадкой.** Первый прогон
  этой сессии (`pnpm test`, 120-секундный лимит вызова) закончился `Failed` на
  `ws-room.test.ts` с `● Timeout` в `room-manager.ts:210`. Я не стала писать это
  как «тесты падают», а проверила: **одиночный** прогон
  `pnpm --filter @balloo/server test` → `EXIT=0`, 721/721; затем **последовательный**
  `pnpm test` → `MONO_EXIT=0` (shared 76, server 721/47, web 266/31, admin 32/3).
  Отличие упавшего прогона: он был запущен **параллельно** со вторым. Оба процесса
  юзают одну и ту же БД `balloo` (`packages/server/.env:7`), а
  `src/__tests__/setup.ts:16-23` прямо документирует лимит Postgres
  `max_connections=100` и пик 97/100 без shared-клиента. Два конкурентных прогона
  = >100 слотов = «remaining connection slots are reserved» = падают нагивании
  запросов в ws-тестах.
  **Правило на будущее: на этой машине `pnpm test` и пакетные прогоны запускаются
  только последовательно.** Это ограничение среды, а не регресс кода.
- **Хэши бандлей — надёжный маркер, если содержимое фронта менялось, и
  ненадёжный, если нет** (правило из `1792812416`). Здесь он надёжен: п.7 сверяет
  хэш **из образа** с хэшем **с домена**, а не с записью в тикете.
- **`pnpm lint` проверкой не является** (заглушки `echo "No linter configured
  yet"`), `typecheck`-скрипта в репозитории нет — типы проверяются только внутри
  `pnpm build`. Не использовать как доказательство.

**Один блок, ≤15 строк команд, read-only по состоянию прода.**

```bash

set -eu
cd /data/balloo/repo
echo "=== 1. КОД ==="
git fetch origin -q && git checkout -B main origin/main 2>&1 | tail -2
echo "HEAD=$(git rev-parse --short HEAD)  MOD=$(git status --porcelain | wc -l)"
echo -n "файлов кода в диапазоне d1dedd6..HEAD: "
git diff --name-only d1dedd6..HEAD | grep -cE "^(packages|docker)/" || true

echo "=== 2. ОБРАЗЫ (возраст решает, что реально крутится) ==="
docker images balloo/server --format "{{.Repository}}:{{.Tag}}  {{.ID}}  {{.CreatedAt}}"
docker inspect balloo-server --format "image={{.Image}} started={{.State.StartedAt}} restarts={{.RestartCount}}"

echo "=== 3. МАРКЕРЫ КОДА В КОНТЕЙНЕРЕ ==="
docker exec balloo-server sh -c "grep -c \"router.use(./api/chats\" packages/server/dist/routes/index.js"
docker exec balloo-server sh -c "grep -c \"Vapid public key\" packages/server/dist/services/pushService.js" || true

echo "=== 4. МАРШРУТЫ (чистый DNS, без --resolve) ==="
for p in "GET /api/onboarding/steps" "POST /api/chats/1/messages" "POST /api/messages/chats/1/messages"; do
  m=${p%% *}; u=${p#* }; printf "%-42s " "$p"
  curl -s -o /dev/null -w "%{http_code}\n" -X "$m" -H "Content-Type: application/json" -d "{}" "https://api.balloo.su$u"; sleep 1
done

echo "=== 5. МИГРАЦИИ ==="
docker exec balloo-postgres psql -U balloo -d balloo -tAc \
  "SELECT count(*) FILTER (WHERE finished_at IS NOT NULL) AS ok, count(*) FILTER (WHERE finished_at IS NULL) AS bad FROM _prisma_migrations;"

echo "=== 6. КОНТЕЙНЕРЫ + ДИСК ==="
docker ps --format "{{.Names}}  {{.Status}}" | grep balloo | sort
df -h / | tail -1
'
```

**Стоп-условия (что делаю при отклонении):**

- `HEAD ≠ 0ca9736` или `MOD ≠ 0` → разбираю, почему `checkout` не применился;
  пересборку не начинаю.
- `CreatedAt` образа = `2026-09-21 …` (`ed70243d4190`) → значит контейнер
  пересоздан из старого образа (ловушка из AGENTS.md): тогда **да**, нужна
  пересборка — выдам батч `build server` + `up -d --no-deps --force-recreate
  server` с откатным тегом `balloo/server:rollback-20261101` как откатную точку.
- п.4: `404` на новый путь или `401` на старый → расхождение с HEAD, возвращаемся
  к диагностике `1793435849`.
- п.5: `bad > 0` → `P3009`, иду в `prisma migrate resolve --rolled-back` по
  разбору `1793435849`, пересоздание контейнера не повторяю.
- `restarts > 0` → снимаю `docker logs --tail 50 balloo-server` до любых
