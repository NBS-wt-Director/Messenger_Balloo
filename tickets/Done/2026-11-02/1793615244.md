## Причина (доказана, а не предположена)

1. Значение `VAPID_PUBLIC_KEY` в `docker/prod/.env.production` — **43 символа
   base64url = 32 байта**. Валидный VAPID public key — несжатая точка P-256,
   **65 байт (86–87 символов)**. Замер (значения не печатались):
   `node -e '…Buffer.from(v,"base64url").length'` → `PUB chars=43 decodedBytes=32`,
   `PRIV chars=43 decodedBytes=32` (приватный корректен, публичный — нет).
2. Живой прогон библиотеки на этих же значениях:
   `node -e 'require("web-push").setVapidDetails(subject, PUB, PRIV)'` →
   `РЕПРО: [Error] Vapid public key should be 65 bytes long when decoded.` —
   ровно сообщение из прод-лога. Контроль: корректная пара от
   `webpush.generateVAPIDKeys()` → `publicKey chars=87 decodedBytes=65`, `OK`.
3. `packages/server/src/services/pushService.ts:42-47` вызывает
   `webpush.setVapidDetails()` **на верхнем уровне модуля**, без try/catch →
   бросок при импорте убивает процесс до `listen()`.
4. **Почему не падало раньше (образ 21.09):** импорт цепочки
   `routes/index.ts:21 → routes/devices.ts → controllers/deviceController.ts:16 →
   pushService` появился в коммите `115d872` (13.10.2026), то есть **внутри
   деплоимого диапазона**. Проверено: `git merge-base --is-ancestor 115d872
   bcf8643` → НЕТ. В старом образе модуль не загружался, бросок не происходил.
5. **Почему тесты зелёные, а прод упал:** в `packages/server/.env` и в CI
   `VAPID_PUBLIC_KEY` пуст → срабатывает `else`-ветка (`console.warn`), броска
   нет. Тест не покрывал «ключ задан, но битый» — закрываю это в п.3.
