# Тикет 1794211606 — OAuth-входы: FORGED_ORIGIN (Яндекс), VK/Mail.ru — консоли провайдеров

**Создан:** 2026-11-09 (unix 1794211606)
**Статус:** в работе
**Источник запроса:** приёмка Шага 7 владельцем в браузере (прод balloo.su)

## Цель
1. Вход через Яндекс → браузер показывает `{"error":"FORGED_ORIGIN"}`.
2. Вход через VK → `{"error":"invalid_request","error_description":"Security Error"}`.
3. Вход через Mail.ru → страница «Не указано приложение… client_id не передан».

## Найденные факты (замеры 09.11.2026, curl с машины)
1. `FORGED_ORIGIN` — ЭТО НАШ middleware: `packages/server/src/middleware/auth.ts:87`
   (`requireSameOrigin`, применён глобально `app.ts:60`). Он принимает в расчёт
   **Referer**: OAuth-callback — это top-level навигация браузера с
   `Referer: https://oauth.yandex.ru/...` → origin `oauth.yandex.ru` нет в
   `CORS_ORIGIN` → 403 JSON. CSRF-защиту callback уже несёт `state` в httpOnly
   cookie (`authController.ts:414-425`, constant-time сравнение) → проверка
   Origin/Referer для callback не нужна.
2. Реальные 302 с прода корректны (проверено curl, кавычек/пустых значений нет):
   - yandex → `oauth.yandex.ru/authorize?…client_id=<32 hex>&redirect_uri=https://api.balloo.su/api/auth/oauth/yandex-callback` — провайдер принял и вернул callback (раз дошёл до нашей 403) → конфиг Яндекса в консоли OK;
   - vk → `oauth.vk.com/authorize?client_id=<8 цифр>&redirect_uri=https://api.balloo.su/api/auth/oauth/vk/callback…` — ошибка «Security Error» выдаёт САМ VK до возврата к нам → настройки приложения VK (домен сайта/статус/redirect_uri);
   - mailru → `connect.mail.ru/oauth/authorize?client_id=<32 hex>&redirect_uri=https://api.balloo.su/api/auth/oauth/mailru/callback…` — client_id ПЕРЕДАН, но Mail.ru говорит «не передан» → их сторона: приложение не активно/не найдено/redirect не согласован.
3. env в контейнере корректны: compose строки 143-151 пробрасывают все 9
   переменных; в `.env.production` значения без CR, длины адекватные.
