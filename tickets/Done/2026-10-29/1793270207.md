**Создан:** 29.10.2026 (unix 1793270207)

## Цель

Яндекс.Метрика (счётчик 112269610) должна инициализироваться в прод-сборке
`packages/web`: ID счётчика должен запекаться в бандль при docker-сборке образа
`balloo/web:local`.

   `VITE_YM_METRIKA_ID` в Dockerfile отсутствует.

скрипт Метрики не загружается и не пытается грузиться — блокировать нечего.

## Проблемы и решения

- **Почему имя бандля на проде не изменилось после пересоздания контейнера
  (batч I, п.3).** Это не провал деплоя: `git diff --diff-filter=AM --stat
  ab1575c..fe602f0 -- packages/web/src` → изменён только один тестовый файл
  (4 удаления), остальные 26 файлов — чистые удаления неиспользуемых
  admin-копий. `git show ab1575c:packages/web/src/App.tsx | grep -i admin` →
  пусто (как и на `fe602f0`), то есть в граф модулей они не входили и в бандль
  не попадали. Содержимое бандля не изменилось → хэш имени тот же.
  Новизна образа доказывается `image=sha256:84da8c18…` (было `fa56089b…`) и
  появлением `mc.yandex.ru` в контейнерном CSP.
  **Отсюда вывод на будущее: для web-деплоя хэш бандля — не маркер, если
  диапазон не трогал исполняемый код. Маркер = ID образа + CSP контейнера.**
- **Риск `web-admin`/`features`:** Метрика ставится только в основном web
  (в CSP админки `mc.yandex.ru` намеренно отсутствует). Переменную добавляю
  в build args только сервиса `web` — не плодить счётчик на админку.
