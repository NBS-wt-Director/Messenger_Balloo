## Что было (замер 19.11.2026)

Механизма кодов авторизации не существовало: 2FA была только TOTP
(`verify2FA` → `verifyTOTP`), кода в push/email не было, push в поток входа
не включён.

## Что сделано (реализация 20.11.2026)

Механизм **кода входа из 13 цифр** с доставкой push/email:

| Слой | Файл | Что |
|---|---|---|
| Сервис | `packages/server/src/services/loginCodeService.ts` (новый) | `generateLoginCode` (13 цифр, `crypto.randomInt`), `resolveCodeChannel` (есть browser-push подписка → `push`, иначе `email`), `issueLoginCode` (хеш sha256(userId:code) в Redis, TTL 300с), `verifyLoginCode` (timing-safe, одноразовый, ≤5 попыток) |
| Почта | `packages/server/src/services/emailService.ts` | `sendLoginCodeEmail` + HTML-шаблон письма с кодом |
| Auth | `packages/server/src/services/authService.ts` | `requestLoginCode(email)` (анти-enumeration: неизвестный email → тот же контракт без отправки); `verify2FA` проверяет 13-значный код **первым**, TOTP/backup — фолбэк |
| Роут | `packages/server/src/routes/auth.ts` | `POST /api/auth/2fa/send-code` |
| Контроллер | `packages/server/src/controllers/authController.ts` | `send2FACode` (400 без email; 503 если Redis недоступен) |
| Web API | `packages/web/src/services/api.ts` | `send2FACode(email)`; `verify2FA(code, email)` — **исправлена передача email** (сервер требует его с самого начала) |
| Web UI | `packages/web/src/screens/auth/TwoFactorScreen.tsx` | режим `login`: автоотправка кода при открытии, подсказка канала («доверенное устройство» / email), поле ввода ровно 13 цифр, кнопка «Отправить снова» с обратным отсчётом |

**Доставка:** если у пользователя есть хотя бы одна browser-push подписка
(`pushSubscription`) — код уходит push'ом на доверенное устройство
(`sendVapidPushToUsers`); иначе — письмом на email. Требование владельца
выполнено буквально.

## Проблемы и решения (если возникли)

- **Найден скрытый баг:** `api.verify2FA(code)` не передавал `email`, а сервер
  требует его (`if (!email || !code) → 400`) — то есть существующий вход по 2FA
  через web-клиент был бы нерабочим. Исправлено: `verify2FA(code, email)`.
- Redis недоступен → `issueLoginCode` бросает `CODE_UNAVAILABLE` (503);
  `verifyLoginCode` возвращает `false` и вход идёт по TOTP/backup — не блокируем вход.
- Реальный SMS-канал не реализуем (нет шлюза) — «SMS» из старого макета убран.
