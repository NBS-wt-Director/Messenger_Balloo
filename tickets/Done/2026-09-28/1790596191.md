## Причина дефекта (подтверждено чтением, 28.09)

| Факт | Где |
| --- | --- |
| Панель append'ится в `document.body` | `mockups/assets/common.js:526` (`document.body.appendChild(menu)`) |
| Позиционирование — `position: fixed; top: 56px; right: 0` | `mockups/assets/common.css:1842-1860` |
| «Экран» мобильного макета — не viewport, а `div.phone-frame` 360×760, `position: relative; overflow: hidden`, отцентрован в body | `mockups/mobile/calls-history.html:10-11` |

`fixed` привязан к viewport браузера, а не к рамке → панель прилипает к правому краю окна,
за пределами «телефона». `overflow: hidden` рамки её не обрезает, потому что она вне дерева рамки.

## Проблемы и решения (если возникли)

1. **Причина дефекта — не «нет мобильных правил», а точка монтирования.**
   `common.js` append'ил панель в `document.body`, а базовый CSS даёт ей
   `position: fixed` → привязка к viewport браузера. Внутри рамки телефона панель
   обрезалась бы `overflow:hidden`, но она была вне дерева рамки. Решение:
   монтировать в `.phone-frame__screen` + абсолютное позиционирование от экрана;
   десктопный путь не тронут (замер после: `1160…1440`, `fixed`).
2. **Мои ошибки этого захода (отменены, в коде их нет):** (а) искала индикатор
   страниц по имени `.page-dots` — такого класса в `mockups/index.html` нет;
   (б) написала в сториборде собственные хелперы `--mobile` (дубль CSS) → штора
   не отрисовалась (`opacity=0`, перебивалась правилами `common.css`), удалено,
   сториборд переведён на живые классы; (в) вставила `<body>` внутрь `<head>` —
   исправлено; (г) попробовала вернуть шеврон ▾ правкой, которой не делала, —
   строки 472/485 в `common.js` остались как в исходном эталоне; (д) опиралась на
   «в common.css есть блок `.phone-frame`» — блока нет (`.phone-frame` определён
   инлайн в каждом мобильном макете), правило `.phone-frame__screen{position:relative}`
   добавила я.
3. **Флаг `data-no-right-menu`** раньше не поддерживался (в `common.js` был только
   `data-no-footer`) — на сториборде живой скрипт построил бы оверлей поверх статичных
   рамок. Добавлена проверка флага в начале `buildRightMenu()`.
4. **Предсуществующее расхождение счётчиков, не чиню молча:** верхний
   `total_screens` = 174, а сумма `total_screens` по всем узлам = 171. Разница 3
   была и до правки (173 против 170). Нужна отдельная ревизия индексов — вне этого тикета.
5. **Не проверено после правок индексов:** `pnpm test`/`pnpm build` не прогонялись
   (правки только в `mockups/` и `scripts/`, `packages/` с момента коммита `d181811`
   не менялся) — в новой сессии прогнать перед коммитом.
7. **Расхождение контракт↔макет по языкам** (замер 28.09): `right-menu.md` обещал
   «20 языков контракта», а `BALLOO_LANGS` (`common.js:36-43`) строит **6**
   (ru, en, zh, fr, be, hi); контракт 20 — `data_schema.json` →
   `conventions.languages`. MD исправлен на факт + отсылку к контракту.
   Разворачивать 20 в общем `common.js` = менять все макеты разом — только по
   решению владельца.
8. **`#viewed-count` ≠ готовность реестра:** JS считает по localStorage-отметкам узлов
   (`DEFAULT_VIEWED_NODES`+`PARTIAL_VIEWED`), в чистом браузере — 40. В баннере числа
   разведены подписями («по реестру» vs «в этом браузере»), чтобы 174 не читалось
   как «всё просмотрено».
9. **Моя ошибка этой сессии (поймана до проверки):** при правке блока счётчиков
   `index.html` я внесла выдуманные имена узлов и продублировала `const PARTIAL_VIEWED`
   (SyntaxError). Поймано `git diff` + `vm.Script` до браузерной проверки; восстановлен
   оригинальный блок из `git show HEAD`, изменено только `TOTAL_SCREENS` и `mobile` 12→24.

6. **Не коммитилось.** Изменено/новое (список снят `git status --short mockups scripts`):
