# Тикет 1793791062 — Реальная доставка сообщений: WS-комнаты чатов не создаются

**Создан:** 04.11.2026 16:17 (unix 1793791062)
**Статус:** готов локально (закрыт 05.11.2026); **на проде не действует до
пересборки `server` и `web`** — батч W в `1793567633` / `with_lord/1793874079`
**Источник запроса:** команда владельца «продолжай» + наружный замер прода
в ходе проверки Шага 7 из `1793567633` (замер 05.11.2026, диагноз 04.11.2026).

## Цель

Главный критерий MVP1 — «отправить и получить сообщение» — должен работать **без
перезагрузки страницы**: получатель, у которого открыт чат, видит новое сообщение
по WebSocket. Сейчас этого нет ни на проде, ни локально. Требуется: интеграционный
тест, доказывающий сбой исполнением → правка сервера и клиента → зелёный тест.

## Диагноз (найдено чтением, **доказывается тестом** — п.1–2 ниже)

1. Клиент web при открытии чата шлёт `{"type":"chat.join","chatId"}`
   (`packages/web/src/screens/chat/ChatViewScreen.tsx:129`).
2. Сервер `chat.join` **не знает**: `switch (parsed.type)` в
   `packages/server/src/ws/handlers.ts:44-89` содержит только `message.send`,
   `message.read`, `typing.start/stop`, `presence.update`, `story.view`,
   `reaction.add/remove`, `call.*`. Неизвестный тип → `error UNKNOWN_TYPE`
   (тест `ws.test.ts:142-149`).
3. `roomManager.joinRoom(chatId, …)` в рабочем коде вызывается **только** с
   `'presence:global'` (`packages/server/src/ws/index.ts:39`) — чатов это не
   касается. Комнаты по `chatId` всегда пусты.
4. `broadcastToRoom(chatId, …)` (`room-manager.ts:134-144`) при пустой комнате
   делает `return` → **получатель не получает `message.received` никогда**.
5. Web-клиент слушает событие `message.send` (`ChatViewScreen.tsx:135`), которого
   сервер не отправляет **вообще** (отправляет `message.received`,
   `handlers.ts:157-170`) — даже при исправленных комнатах клиент его не обработает.
6. Web отправляет сообщения **через REST** (`api.sendMessage`,
   `ChatViewScreen.tsx:201`), а REST-путь (`controllers/messageController.ts:39`
   → `services/messageService.ts:68`) **не делает никакой broadcast** — в
   контроллерах `roomManager` не используется ни разу (замер grep'ом 04.11).
7. WS-путь `message.send` (`handlers.ts:157-182`) кладёт в исходящее событие
   `timestamp: message.createdAt` — это **BigInt**, а `serializeWsMessage` —
   обычный `JSON.stringify` (`types.ts:321`) → `TypeError: Do not know how to
   serialize a BigInt`, промис отвергается, `index.ts:74-83` отвечает
   `error INTERNAL_ERROR`. Сообщение в БД создаётся, но подтверждение и рассылка
   не доходят. (Проверяется тестом — не утверждается на глаз.)
8. Тесты `ws-room.test.ts` зовут `rm.joinRoom('chat1', conn)` **напрямую**, минуя
   протокол, поэтому зелёные при полностью неработающей доставке. Это и есть
   «зелёный тест, который ничего не доказывает» (§0.1 п.4).

## Проблемы и решения

- **Зелёные тесты при неработающей фиче.** `ws-room.test.ts` проверял
  `RoomManager` напрямую (прямой вызов `joinRoom`), а не протокол, поэтому
  3 месяца не замечал, что комнат чатов никто не создаёт. Решение: новый набор
  идёт только через сеть (реальный `http.Server` + `WebSocketServer` + два
  реальных WS-клиента + `supertest` для REST); прямой вызов `joinRoom` в тестах
  доставки отсутствует.
- **Двойной путь создания сообщения.** WS-хендлер сам делал `prisma.message.create`
  и не обновлял `unread`/`lastMessage` — на проде это означало бы «сообщение
  пришло, но в списке чатов не отобразилось». Решение: WS-хендлер вызывает
  тот же `sendMessageService`, что и REST-контроллер.
- **Расхождение дат в записях (моя ошибка, исправлена).** Замеры и половина правок
  сделаны 04.11.2026 (16:17–16:34), продолжение — 05.11.2026 (15:09–15:25);
  в `docs/04-api-websocket-spec.md` и `tickets/active/1793873744.md` я сначала
  поставил 04.11 везде. Проверено по `ls -la --time-style=full-iso` и `date`,
  даты исправлены на фактические. Хронология: тест красный — 04.11 16:26;
  web-тест и error-mapping — 05.11 15:12–15:19.
- **Временный файл `/tmp/ChatViewScreen.bak.tsx`** использовался только для
  доказательства регрессии web-теста; рабочий файл восстановлен из него,
  `grep -c "case 'message.received'"` → 1. Вне воркспейса ничего не создавалось.
