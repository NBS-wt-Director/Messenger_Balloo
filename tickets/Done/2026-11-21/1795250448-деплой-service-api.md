## Что меняется

Серверные эмуляционные эндпоинты `/api/service/*`, закрытые длинным ключом
(`SERVICE_API_KEY`, заголовок `X-Service-Key`). Фронтенд НЕ меняется — деплоится
только контейнер `server` (API). Порядок по KODA.md «сначала API, затем web»:
web можно не пересобирать, т.к. его код не тронут.

Изменённые файлы:
- `packages/server/src/middleware/serviceAuth.ts` (новый)
- `packages/server/src/controllers/serviceController.ts` (новый)
- `packages/server/src/routes/service.ts` (новый)
- `packages/server/src/routes/index.ts`, `config/env.ts`, `middleware/rateLimit.ts`
- `docker/prod/docker-compose.local.yml`, `docker-compose.prod.yml` (проброс `SERVICE_API_KEY`)
- `.env.production.example` (заготовка ключа), `.gitignore` (`docs/local/`)
- `scripts/server_routes.txt` (перегенерация дампа, 293 маршрута)

## ВАЖНО: ключ на проде

`SERVICE_API_KEY` **отсутствует** в `docker/prod/.env.production` — его надо
добавить на сервере (батч E). Без него все `/api/service/*` отвечают `404`
(фича выключена — это безопасно, но эмуляция не работает).

- Сгенерировать на сервере: `openssl rand -hex 32`
- Добавить строку `SERVICE_API_KEY=<значение>` в `docker/prod/.env.production`
- Значение — только на сервере и в локальном `docs/local/service-api.md` (вне git)
