# Задачи (tasks/)

## Структура

```
tasks/
 README.md          ← этот файл (правила работы)
 TASKS.md           ← единый реестр задач со статусами и командами проверки
 current/           ← задачи, которые можно делать прямо сейчас (проверено)
 next/              ← задачи, следующие после current (в процессе валидации)
 inbox/             ← идеи и вопросы, ещё не оформленные в задачи (пусто)
```

## Правила для AI-агента

### 🔴 Правило 1: никогда не доверяй статусу без проверки

Каждая строка в `TASKS.md` содержит поле `verification`. **Перед тем как
считать задачу выполненной — запусти эту команду и убедись что результат совпадает.**

Если поле `verification` пустое — задача требует написания команды проверки.

### 🔴 Правило 2: один результат = один коммит

Каждый завершённый шаг = отдельный коммит с понятным message.
Не копить правки в «одном большом коммите».

### 🔴 Правило 3: что «DONE» — переносить в archive

Если задача закрыта и проверена — перемещай файл из `current/` или `next/`
в `tasks/archive/`. В начале перемещённого файла — заголовок:

```
# TASK_ID — название [ЗАКРЫТО]
> Перенесено из current/ в archive/ ДД.ММ.ГГГГ
> Коммит закрытия: <short-hash>
> Результат проверки: вывод команды
```

### 🔴 Правило 4: новая задача = новая строка в TASKS.md

Перед началом работы:
1. Найди задачу в `TASKS.md` по ID
2. Если задачи нет — создай строку в разделе `next/` с полями:
   - `status: TODO`
   - `verification: <пусто>` (потом заполню)
   - `priority: HIGH|MEDIUM|LOW`
3. Перемести файл из `inbox/` в `next/` или `current/`

### 🔴 Правило 5: проверять перед каждым запуском

Перед началом работы в любой сессии:
1. `git status` — проверить что нет незакоммиченного
2. `pnpm test` — убедиться что тесты зелёные
3. Прочитать `TASKS.md` и `current/` — понять что делать дальше

### 🔴 Правило 6: писать что делаешь

Если задача не в `TASKS.md` — не делай её. Если задача в `TASKS.md` —
не делай без коммита и проверки.

### 🟢 Правило 7: не переписывать историю

Только fast-forward push. Никаких `--force`, `--force-with-lease`,
`rebase` опубликованных веток.

## Как читать TASKS.md

| Поле | Описание |
|---|---|
| ID | Уникальный идентификатор задачи |
| Название | Краткое описание |
| Область | web / server / shared / ui / infra / docs |
| Статус | `TODO` / `IN_PROGRESS` / `DONE` / `BLOCKED` |
| Приоритет | `HIGH` / `MEDIUM` / `LOW` |
| Проверка | Команда для верификации |
| Доказательство | Что именно должно быть в выводе команды |
| Источник | Ссылка на файл-источник (если перенесено) |
