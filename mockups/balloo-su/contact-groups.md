## Макет
`balloo-su/contact-groups.html`

## Пользовательская ситуация

Мария хочет публиковать истории только для близких, а рабочих — держать
отдельно. Она создаёт две группы контактов: «Семья» (муж, мама, сестра) и
«Коллеги» (4 человека из отдела). При создании истории выбирает
«выборочный доступ» → «Группы» → отмечает «Семья» — история доступна всем
участникам группы, без ручного выбора каждого контакта. Группы видны только
Марии; контакты не узнают, в какие группы они добавлены.

## Описание страницы

Управление **списками контактов** (именованными группами «для себя») —
не путать с чатами-группами (`group-create.html`). Двухпанельная страница:
sidebar со списком групп (по образцу «Контакты»), content — сводка, карточки
групп с превью участников, модалки создания/редактирования и удаления.
Вход: вкладка «👥 Группы» экрана «Контакты» (переход сюда) и прямая ссылка из
`story-create.html` при «выборочном доступе».

## Структура страницы

### Topbar
- Логотип Balloo с dropdown навигацией
- Заголовок «Группы контактов»
- Кнопка 📨 → `invites.html`
- Аватар → `profile.html`, язык, тема

### Sidebar — Список групп
- Поиск групп (фильтрация на лету)
- Элемент списка: аватар-октагон с эмодзи группы, название, «N участников»
- Активная группа — `list__item--active`
- Кнопка «➕ Новая группа» (primary, block) внизу sidebar — открывает модалку

### Content
1. **Плашка «предварительный макет»** (info-тон) — убрать после приёмки
2. Заголовок «👥 Группы контактов» + подзаголовок + кнопка «➕ Создать группу»
3. **Вкладки** (как в `contacts.html`): «Контакты» → `contacts.html` /
   «👥 Группы» (active) / «🚫 Чёрный список» → `blocked-users.html`
4. **Сводка** (2 stat-карточки, образец `blocked-users.html`):
   количество групп; уникальных контактов, состоящих в группах (из всего числа)
5. **Карточки групп** (один card, divider между строками):
   - аватар-октагон (md) с эмодзи группы
   - название; превью участников — 3–4 аватара-sm + «+N ещё»
   - мета: «Обновлена ДД.ММ.ГГГГ · используется в N историях»
   - кнопки: «✏️ Изменить» (secondary) / «🗑» (tertiary, с подтверждением)
6. **Empty state** при 0 групп (`.empty-state`, CTA «Создать группу»)
7. **Card «Где используются группы контактов»**: ссылка на `story-create.html`
   (выборочный доступ), чипы групп в профиле контакта, приватность групп

### Modal: создание/редактирование группы
- Название * (до 60 символов)
- Эмодзи группы (select: 👥 💼 ❤️ 🎓 🤝 ⚽ 🎸 🏡)
- Описание (до 200 символов)
- **Пикер участников**: поиск + чекбокс-список контактов (аватар, имя,
  статус) — образец блок «Пригласить участников» из `group-create.html`;
  «Выбрать все», счётчик «Выбрано: N»
- Кнопки: Отмена / 💾 Сохранить

### Modal: удаление группы
- `modal--status-danger`; текст: контакты остаются, опубликованные
  истории сохраняют уже выданный доступ
- Кнопки: Отмена / Удалить (danger)

## Функционал
- **CRUD групп** — создание, переименование, смена эмодзи/описания, удаление
- **Состав группы** — добавление/исключение контактов; контакт может состоять
  в нескольких группах
- **Поиск по группам и по контактам внутри пикера**
- **Использование в историях** — при «выборочном доступе» переключатель
  «Контакты / Группы»; выбор группы = выбор её состава на момент публикации
- **Приватность** — группы и состав видны только владельцу; удаление группы
  не отзывает доступ уже опубликованных историй (снимает только будущие)

## Дизайн-требования
- Дизайн-система: `mockups/assets/common.css` (glassmorphism-карточки,
  октагоны, без border-radius кроме switch/аватарок)
- Активная вкладка — `btn--primary btn--sm`, неактивные — `btn--tertiary`
- Аватары группы — ctx-классы (`avatar--ctx-family` / `--ctx-new` /
  `--ctx-contact`) с эмодзи внутри
- Toast-уведомления о сохранении/удалении — `.toast-container` (реализация
  как в `chats.html`)
- Удаление — только через подтверждающую модалку, никогда по одному клику

## Компоненты
- `ContactGroupList` — sidebar со списком групп
- `ContactGroupListItem` — элемент (аватар-эмодзи, название, счётчик)
- `ContactGroupCard` — карточка группы в content (превью участников, действия)
- `ContactGroupEditorModal` — форма + пикер контактов
- `ContactPicker` — переиспользуемый чекбокс-список контактов
  (общий с `group-create.html` и `story-create.html`)
- `ConfirmDeleteModal` — общее подтверждение удаления

## API
- `GET /api/users/contact-groups` — список групп владельца (+ memberCount, превью)
- `POST /api/users/contact-groups` — создать {name, emoji, description, memberIds[]}
- `PATCH /api/users/contact-groups/:id` — изменить состав/поля
- `DELETE /api/users/contact-groups/:id` — удалить группу
- `GET /api/users/contact-groups/:id/members` — полный состав
- Stories: `POST /api/stories` расширяется полем `audienceGroupIds[]`
  (состав разворачивается в `StoryAudience` на момент публикации)

## Сущности данных (`3_01_xx`, plan)
- `ContactGroup` — id, ownerId, name, emoji, description, createdAt, updatedAt
- `ContactGroupMember` — groupId, memberId (контакт-пользователь), addedAt;
  FK на обоих концах, unique (groupId, memberId)

## WebSocket
- Опционально, на этапе v2: `contact_group:updated` — мгновенное обновление
  пикера у открытого клиента. В MVP1 допустимо обновление REST-запросом.
