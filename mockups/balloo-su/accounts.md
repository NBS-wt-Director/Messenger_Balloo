# Задание: balloo.su — Аккаунты (мультиаккаунт)

## Макет
`balloo-su/accounts.html`

## Описание страницы
Страница управления подключёнными аккаунтами (мультиаккаунт). Доступна из профиля (карточка «Аккаунты» → «Управлять»). Неограниченное количество аккаунтов. Только для основного узла balloo.su, на всех платформах.

## Структура страницы

### Topbar
- Логотип Balloo, кнопка «← Назад» в профиль
- Аватар, язык, тема

### Content (narrow, max-width 640px)
1. **Ссылка** «← Назад в профиль»
2. **Заголовок** «👥 Аккаунты»
3. **Подзаголовок** «Управление подключёнными аккаунтами. Неограниченное количество.»
4. **Карточка быстрого переключения**:
   - Горизонтальный список чипов аккаунтов (аватар-октагон + имя)
   - Активный аккаунт — accent border + фон
   - Кнопка «+» (dashed accent border) → `login.html`
   - Подсказка: «Нажмите для переключения. Уведомления для всех.»
5. **Карточки статистики** (3): Всего аккаунтов / Уведомлений включено / Активный
6. **Карточка активного аккаунта** (accent border):
   - Chip «Активный аккаунт» + «Сейчас в сети»
   - Аватар-октагон, имя, email · @username · ссылка
   - Метаданные: чатов, контактов, непрочитано, уведомления
   - Кнопки: Настройки профиля / Уведомления (toggle)
7. **Карточки других аккаунтов** (по 1 на аккаунт):
   - Аватар-октагон, имя, email · @username · чаты · непрочитанные
   - Кнопки: Переключить (primary) / Уведомления (🔔/🔕 toggle) / Отключить (danger)
   - Доп. инфо: уведомления, последняя активность, дата подключения
8. **Кнопка** «➕ Добавить аккаунт» → `login.html`
9. **Карточка «Как работает мультиаккаунт»**:
   - Чаты и контакты — свои у каждого аккаунта, только активный
   - Уведомления — для всех одновременно с пометкой аккаунта
   - Переключение — мгновенное, без повторного входа
   - Тема и язык — общие (синхронизируются)
   - Устройства — общие для всех аккаунтов
   - Отключение — сессия удаляется, данные остаются
   - Лимит — неограниченно
10. **Карточка «Уведомления мультиаккаунта»**:
    - Метка аккаунта (имя/аватар) в каждом уведомлении
    - Группировка по аккаунту
    - Тап на уведомление → переключение + открытие чата
    - Индивидуальное отключение уведомлений (🔔/🔕)

## Функционал
- **Быстрое переключение** — клик на чип аккаунта, мгновенная смена контекста (чаты, контакты)
- **Переключить** — кнопка в карточке аккаунта, подтверждение
- **Добавить аккаунт** — переход на `login.html` (вход с другим email/OAuth)
- **Отключить аккаунт** — удаление сессии аккаунта на этом устройстве, данные остаются
- **Уведомления toggle** — индивидуальное вкл/выкл push для каждого аккаунта (🔔/🔕)
- **Настройки профиля** — переход в `profile.html` для активного аккаунта

## Компоненты
- `AccountSwitcher` — горизонтальный список чипов аккаунтов с быстрым переключением
- `AccountCard` — карточка аккаунта с действиями (переключить, уведомления, отключить)
- `AccountStatsGrid` — сетка статистики
- `AccountAddButton` — кнопка добавления (dashed)
- `MultiAccountInfo` — информационная карточка
- `NotificationToggle` — toggle уведомлений аккаунта

## API
- `GET /api/v1/accounts` — список подключённых аккаунтов на устройстве
- `POST /api/v1/accounts/switch` — переключение активного аккаунта
- `POST /api/v1/accounts/add` — добавление аккаунта (login flow)
- `DELETE /api/v1/accounts/:id` — отключение аккаунта (сессия удаляется, данные остаются)
- `PATCH /api/v1/accounts/:id/notifications` — вкл/выкл уведомлений для аккаунта
- `GET /api/v1/accounts/:id/stats` — статистика аккаунта (чаты, контакты, непрочитанные)

## WebSocket
- `account:switch` — событие переключения аккаунта (сервер переключает WS-контекст)
- `account:added` — новый аккаунт подключён
- `account:removed` — аккаунт отключён
- `account:notification` — уведомление с меткой аккаунта (для всех аккаунтов одновременно)

## Адаптивность
- Desktop: page-container--narrow
- Mobile: полный экран, чипы скроллятся горизонтально
- Desktop sidebar: пункт «Аккаунты» в навигации

## Технологии
- React 19 + Next.js
- Zustand: `accountStore` (activeAccountId, accounts[], switchAccount, addAccount, removeAccount)
- WebSocket: мультиплексирование — один WS, несколько аккаунтов (account_id в payload)
- Push: метка аккаунта в уведомлении (title prefix или avatar)
- Сессии: каждый аккаунт имеет свой JWT, хранятся в зашифрованном виде на устройстве
