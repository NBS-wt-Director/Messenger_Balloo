# Экран ошибки 503 — Сервис недоступен

> **ID:** `1_00_04`  
> **Узел:** `shared` (общие экраны)  
> **Используется в:** все узлы, кроме `docs-balloo-su`

---

## Описание

Страница отображается, когда сервис временно недоступен (технические работы, перегрузка). Общий экран для всех узлов монорепо (кроме docs.balloo.su).

## Структура

- **topbar** — минимальный: лого, заголовок «Ошибка 503», маскот, переключатели
- **content** — центрированный блок:
  - Маскот 🦊🔧
  - Код ошибки `503` (крупный, цвет `var(--text-muted)`)
  - Заголовок «Сервис недоступен»
  - Описание
  - Кнопки: «Обновить», «Статус сервиса» (ссылка на Telegram/статус-страницу)

## Дизайн-требования

- Дизайн-система: `mockups/assets/common.css`
- Цвет кода ошибки: `var(--text-muted)` (нейтральный) — не пугает, информирует
- Без border-radius
- Темы: dark, light, russian

## Компоненты (React)

- `<ErrorScreen code={503} mascot="🦊🔧" title="Сервис недоступен" variant="muted" />`

## API

- Нет API-вызовов — статическая страница
- Сервер отдаёт `Retry-After` header

## Адаптивность

- Mobile: код ошибки 80px, кнопки в столбик

## Технологии

- React + TypeScript
- Общий компонент `ErrorScreen` в `packages/shared/src/components/`
- SSR-совместимый (отдаётся сервером при 503)

## Сохранение событий в логи (В-1…В-8)

При показе экрана (ошибка/офлайн/бан) клиент отправляет событие на сервер:

- **Эндпоинт:** `POST /api/client-errors`
- **Тело запроса:** `{ code, url, referrer, userAgent, userId?, timestamp }`
- **Где хранится:** серверный лог (console/file) + запись в `AuditLog` (Prisma) + `ServiceMetric`-счётчик `client_error:<code>`
- **Кто читает:** админ-панель → раздел «Аудит-лог» (фильтр по типу `client_error`), дашборд метрик
