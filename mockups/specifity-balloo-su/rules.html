Правила проектирования и разработки

Единые правила для всего монорепо: порядок проектирования функциональности, система нумерации объектов, жизненный цикл, дизайн-система и статусы реализации. Источник — AGENTS.md.

Порядок проектирования функциональности
Применяется при добавлении любой новой функции. Никогда не начинать с сущностей данных или эндпоинтов — сначала «что и зачем», потом «как выглядит», потом «как устроено под капотом».
Функция (0_xx_yy)
Что делает новый функционал, какая бизнес-задача решается.
Узел (у_xx)
Какому узлу (домену) принадлежит функция. Если затрагивает несколько узлов — описывается для каждого.
Пользовательская ситуация
Сценарий использования: кто, что делает, в какой последовательности, какой результат.
Экраны (1_xx_yy)
Какие UI-экраны нужны для функции по ситуациям.
Эндпоинты + Компоненты (2_xx_yy + 4_xx_yy)
API-эндпоинты и UI-компоненты, обслуживающие экраны.
Сущности данных (3_xx_yy)
Таблицы/модели БД для хранения данных функции.
Система нумерации объектов
Все объекты имеют уникальный ID в формате z_xx_yy: z — префикс типа, xx — номер узла (01–99, 00 = shared), yy — порядковый номер внутри узла.
ПрефиксТип объектаПример
уУзел (node)у_01 — balloo.su
0Функция (function)0_01_03 — функция №3 узла 01
1Экран (screen)1_01_04 — экран №4 узла 01
2API-эндпоинт2_01_05 — эндпоинт №5 узла 01
3Сущность данных3_01_02 — сущность №2 узла 01
4Компонент4_01_01 — компонент №1 узла 01

Узел 00 — зарезервирован для общих экранов (shared/). Нумерация внутри узла независима. ID не меняются при правках и не переиспользуются при удалении.

Жизненный цикл проекта
ФазаНазваниеЧто происходит
1Проектирование макетовТекущая фаза. Макеты — источник правды. Правки вносятся по замечаниям пользователя.
2Фиксация документацииПо команде «зафиксируй документацию». Макеты замораживаются, генерируется docs/ + README.md.
3РазработкаМакеты только для чтения. Код в packages/ должен 100% совпадать с макетами.
4v2По команде пользователя. Макеты снова можно менять, новый цикл правок.
Порядок обработки замечаний по макетам
1. Внести правку в макет
HTML-файл макета в mockups/<узел>/. Соблюдать дизайн-систему common.css.
2. Создать/обновить MD рядом с макетом
Задание на создание работоспособной страницы: структура, компоненты, API, адаптивность.
3. Обновить index.html
Карточка экрана, счётчики, баннер готовности.
4. Обновить index_ecrans.md
Сводная таблица узлов, запись экрана, функции.
5. Обновить index_ecrans.json
Метаданные (JSON), счётчики, last_updated.
6. Обновить docs/
При новой функции — архитектура, требования, БД, API, фронтенд, devops.
Дизайн-система (краткая справка)
Подробно — в mockups/assets/common.css. Эталон тем — mockups/index.html. Темы зафиксированы, замечания по ним игнорируются до Фазы 2.
