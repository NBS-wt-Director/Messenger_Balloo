## 2. ДЕТАЛЬНЫЙ АНАЛИЗ ПО ДОКУМЕНТАМ

### 2.1 Политика конфиденциальности (152-ФЗ)

**Что должно быть в документе:**

## 3. АКТУАЛЬНЫЕ НПА (на 01.09.2026)

### 3.1 Федеральные законы

#### ФЗ-152 «О персональных данных» (ред. от 2024-2025)

**Ключевые изменения 2025-2026:**
- **С 01.07.2025:** Ужесточены требования к локализации БД ПД граждан РФ
- **С 01.09.2025:** Новые штрафы по ст. 13.11 КоАП (в 5-10 раз выше)
- Обязательная регистрация операторов ПД в реестре РКН
- Обязательное назначение ответственного за ПД
- Обязательная оценка вреда субъектам ПД

**Требования к мессенджеру:**
1. Базы данных с ПД пользователей должны храниться на серверах в РФ (ст. 18.1)

3. Политика конфиденциальности — публичный документ (ст. 18.1)
4. Уведомление в РКН — в течение 1 месяца начала обработки (ст. 22)
5. Обеспечение безопасности ПД — организационные и технические меры (ст. 19)
6. Удаление ПД по требованию субъекта (ст. 21)
7. Экспорт ПД по требованию субъекта (ст. 14)

## 4. АНАЛИЗ КОДА С ПРАВОВОЙ ТОЧКИ ЗРЕНИЯ

### 4.1 Какие ПД собирает Balloo

**Из `schema.prisma` и кода:**

| Поле | Таблица | Категория ПД | Требуется согласие? |
|---|---|---|---|
| email | users | Обычные | Да |
| username | users | Обычные | Да |
| passwordHash | users | Специальные (биометрия) | Да, письменное |
| phone | users | Обычные | Да |
| avatarUrl | users | Обычные | Да |
| displayName | users | Обычные | Да |
| language | users | Обычные | Да |
| status | users | Обычные | Нет |
| ip_address | devices | Специальные | Да |
| device_info | devices | Специальные | Да |
| push_token | devices | Обычные | Да |
| chat_content | messages | Специальные (тайна переписки) | Да, письменное |
| media_files | message_attachments | Специальные | Да, письменное |
| location | — | Не собирает | — |

**Вывод:** Balloo собирает **расширенный набор ПД**, включая содержание переписки (ст. 23 Конституции РФ — тайна переписки). Требуется:
1. Письменное согласие на обработку ПД
2. Письменное согласие на хранение метаданных переписки
3. Политика хранения и удаления сообщений

---

### 4.2 Хранение паролей (проблема безопасности)

**Файл:** `authService.ts:91`

```typescript
const hashPassword = (password: string): string =>
  crypto.createHash('sha256').update(password + 'balloo-salt-2024').digest('hex');
```

**Правовой аспект:**
- Ст. 19 152-ФЗ: оператор обязан обеспечить **безопасность** ПД
- SHA-256 без salt (хардкод salt — это не salt) НЕ является достаточной мерой защиты
- При утечке базы данных все пароли могут быть взломаны
- Это нарушение ст. 19 152-ФЗ и ст. 13.11 КоАП РФ

**Требование ФСТЭК (Приказ №21):**
- Использование сертифицированных средств защиты
- Хеширование паролей с использованием salt и.iterations (bcrypt/argon2)
- Регулярная ротация ключей шифрования

---

### 4.3 Тайна переписки (ст. 23 Конституции РФ)

**Факт:** Balloo — мессенджер. Он хранит и передаёт сообщения между пользователями.

**Требования:**
1. Ст. 23 Конституции РФ: тайна переписки, телефонных переговоров
2. ФЗ-126 «О связи»: операторы связи обязаны обеспечивать конфиденциальность
3. ФЗ-63 «Об электронной подписи»: электронные сообщения имеют юридическую силу

**Статус в коде:**
- Сообщения хранятся в БД (`messages` таблица)
- WebSocket для real-time доставки
- Нет явного указания на E2EE для обычных чатов
- Секретные чаты (E2EE) — только в UI, без бэкенд-реализации

**Вывод:** Пользователи должны быть информированы о том:
1. Хранятся ли сообщения на сервере
2. Имеет ли администратор доступ к содержимому сообщений
3. Как долго хранятся сообщения
4. Как удалить сообщения

## 7. РЕКОМЕНДАЦИИ

### 7.1 Немедленно (до любого публичного запуска)

1. **Написать политику конфиденциальности** — нанять юриста, специализирующегося на 152-ФЗ
2. **Написать пользовательское соглашение (оферту)** — с учётом специфики мессенджера
3. **Заменить SHA-256 на bcrypt/argon2** — критическая уязвимость
4. **Подать уведомление в РКН** — в течение 1 месяца начала обработки ПД
5. **Настроить локализацию БД** — PostgreSQL на сервере в РФ
6. **Разместить документы на сайте** — `/privacy`, `/rules`, `/cookies`

### 7.2 В течение 1 месяца

7. Написать политику cookies
8. Написать NDA для сотрудников
9. Настроить удаление аккаунта и экспорт ПД (требование 152-ФЗ)
10. Настроить политику хранения и удаления сообщений
11. Рассмотреть E2EE для всех чатов (не только «секретных»)

### 7.3 В течение 3 месяцев

12. Пройти сертификацию ФСТЭК (если цель — госсектор)
13. Зарегистрироваться в реестре российских мессенджеров
14. Подготовить адаптацию под законодательство ЕАЭС
