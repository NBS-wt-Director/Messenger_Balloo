# Баллу — архитектура безопасности

**Проверено по коду:** 08.10.2026, коммит `7697e43`, структура `packages/*` (web, server, shared, desktop).
Каждый механизм ниже подтверждён grep'ом по файлам из раздела «Ключевые файлы» — ничего не «должно быть», всё «есть».

Для кого: для того, кто меняет код и не должен сломать защиту. Сначала раздел «Контракт», потом «Что можно менять».

## 1. Модель угроз — что реально защищаем

| Актив | Чем защищён |
|---|---|
| Сессия пользователя (JWT 15 мин) | подпись HS256, `jti`-блок-лист, httpOnly-cookie |
| Смена телефона/пароля | SMS-код 6 цифр + подпись `code_hash`/`code_salt` + срок жизни |
| Восстановление доступа | одноразовый токен (24 ч, digest в БД, `used_at`) |
| Резюме в Telegram | HMAC подписанный `initData`, проверка `auth_date` |
| Чужие данные (DB shared) | обязательный `owner_id`/`user_id` в фильтре каждого запроса |
| XSS, кликджекинг | CSP + заголовки helmet на сервере, `frame-ancestors 'none'` |
| Брутфорс кодов/входа | лимит попыток в `auth_verification` + `maxAgeMs` в куке |

## 2. Контракт безопасности (нормативный — менять только с осознанным риском)

1. **JWT** (`packages/server/src/services/jwt.ts`): доступ 15 мин, `issuer=balloo.ru`, `audience=balloo-web`, HS256. Секрет из `JWT_SECRET`, в проде обязателен — иначе `process.exit(1)`.
2. **Блок-лист токенов**: каждый токен несёт `jti`; при смене телефона/выходе текущий `jti` уходит в Redis (`SET jti logout TTL=15м`) и/или таблицу `revoked_tokens`. Проверка — в `authenticate`.
3. **SMS-код**: 6 цифр (`100000..999999`), `code_hash = HMAC-SHA256(код, salt)`, `code_salt` — отдельный secret; срок `SMS_CODE_TTL_MIN` (по умолчанию 5 мин); **до 5 попыток**, далее `429`.
4. **Телефон**: канон `+7XXXXXXXXXX` — единственное место нормализации `normalizePhone` (`packages/shared/src/phone.ts`). Весь ввод проходит через неё **до** любых вставок в SQL.
5. **Транспорт токенов**: `httpOnly` + `secure` + `sameSite=lax`, `maxAge = expiresIn + 60 000`. Доступен только на домене `.balloo.ru` (поддомены `t.balloo.ru`/`e.balloo.ru` — отдельные cookie, их не читают).
6. **Заголовки** (`packages/server/src/middleware/security.ts`, helmet): CSP c `frame-ancestors 'none'`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, HSTS в проде. CSP подаётся **HTTP-заголовком на сервере**, не `<meta>` в index.html — это правильные два места, дублировать не надо.
7. **Шифрование PII** (`encryption.ts`): AES-256-GCM, ключ `DATA_ENCRYPTION_KEY`, формат `iv:tag:ciphertext` (base64).
8. **initData Telegram** (`telegram.ts`): `secret_key = SHA256(initData)`, подпись проверяется по алгоритму Telegram; при `test=1` — фикстура `TEST_INIT_DATA_HASH` (тесты не требуют живого бота).
9. **SQL**: только параметрированные запросы (`$1…$n`), имена таблиц/колонок — литералы кода, никогда не пользовательские строки.
10. **Ограничение доступа к чужим строкам**: каждый запрос к таблицам с общими строками фильтруется по `owner_id`/`user_id` из `req.user`.
11. **CORS**: белый список origin'ов (`CORS_ORIGINS`), `credentials: true`. Никаких `*`.
12. **Логи**: секреты и коды в лог не пишутся; `console.log` только факт («otp отправлен», без значения).

## 4. Тестовый контракт безопасности (обязательные проверки)

Есть сейчас (`packages/server/src/__tests__/`):
- `auth.suggest-accounts.test.ts` — нельзя получить чужие аккаунты по телефону;
- `auth.phone-normalization.test.ts` — обход формата не проходит;
- `security.test.ts` + `security-headers.test.tsx` — заголовки/CSP на месте;
- `packages/web/src/router/router-guards.test.tsx` — приватные роуты без сессии редиректятся.

Должно появиться вместе с §5 (и это часть приёмки, не «потом»):
- 6-й неверный код → `429` и код не принимается;
- повторное использование restore-токена → отказ (`used_at`);
- истёкший restore-токен → отказ;
- запрос к чужой строке (подменный id) → пусто/403;
- кука без `Secure` в проде не выставляется.

## 5. Что осталось сделать (внедрение, по одному заход)

1. **Rate limit HTTP** — `express-rate-limit`: `POST /auth/*` 10/мин на IP, остальное 100/мин. Сейчас лимит только внутри `auth_verification`.
2. **Refresh-механика** — доступа 15 мин, refresh нет; пользователь «выпадает». Решение: refresh httpOnly + `POST /auth/refresh` + `rotation`.
3. **Input-схемы на оставшихся роутах** — в `routes/auth.ts` есть `sendOtpSchema`/`verifyOtpSchema`, проверить сквозное покрытие всех POST-эндпоинтов (не только auth).
4. **Страница 429** — клиент сейчас не различает «потом» и «ошибка».
5. **Мониторинг DMARC** — `p=none` без отчётов = не видно, кто шлёт от balloo.ru. Включить `rua` и смотреть раз в неделю.
6. **Второй ключ шифрования** — `DATA_ENCRYPTION_KEY` один на всё; при компрометации расшифровывается всё. План ротации (key version в префиксе значения).

Мелкие замечания по текущему коду (не блокер):
- `resolveGoogleToken`/`resolveGithubToken` в `utils/validation.ts` — пустые заглушки, возвращают `''`; не использовать как «проверено».
- Предыдущий аудит угроз: `docs/security-audit.md` (2026-06, OWASP-проверка текущего кода) — этот документ
  описывает **архитектуру**, тот — **что уже проверено и что найдено**. Пересекаться будут, читать оба.

## 6. Что можно менять не сломав

- Цвета, тексты, раскладка, компоненты — `packages/web/src/` (без изменения guard'ов).
- Добавление новых полей в формы — если они проходят через zod-схему и не попадают в SQL конкатенацией.
- Добавление новых роутов — с `requireAuth` (или явным публичным списком) и `<Route path="*">` = `NotFoundScreen` остаётся последним.
- SQL — свободно, но параметрированно и с фильтром по владельцу.
- TTL токенов/лимиты попыток — констаны в начале `routes/auth.ts` и `services/jwt.ts`, менять можно, контракт (§2) тогда правь здесь же.

## 7. Что не менять без смены контракта

- `normalizePhone` — единственная точка нормализации. Не писать свои regex телефона в компонентах.
- `sameSite`, `httpOnly`, `secure`, домен cookie.
- Проверку `jti` в `authenticate` и блок-лист при смене телефона/выходе.
- `jti` в токенах восстановления (иначе отзыв перестанет работать).
- `code_hash`/`code_salt` (переход на «хранить код в открытом виде» запрещён).
- `frame-ancestors 'none'` в CSP.
- `owner_id`/`user_id` в фильтрах выборок.
