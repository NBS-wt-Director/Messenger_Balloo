## 📜 4. Правила Взаимодействия

### 4.1. Приоритеты
1. **Макеты (`mockups/`) — единственный источник правды.** Если код противоречит макету — правим код.
2. **Документация `docs/` — производная от макетов.** Не меняем логику, если макет не изменён.
3. **Безопасность > Оптимизация.** На первом этапе приоритет: корректность, защита от инъекций, валидация, RBAC.
4. **Никаких предположений.** Если параметр не указан → вопрос пользователю. Никаких `TODO` или `// FIXME` без комментария.

### 4.2. Формат Ответов
- **Код:** Только в блоках с указанием полного пути к файлу.
- **Объяснения:** Максимум 2-3 предложения. Без воды.
- **Шаги:** Нумерованный список действий перед генерацией кода.
- **Ошибки:** При сбое сборки/тестов → анализ лога → точечная правка → повторная проверка.

### 4.3. Запреты
- ❌ Не генерировать файлы вне `packages/`, `mockups/`, `docs/`, `docker/`.
- ❌ Не менять дизайн-систему (`common.css`) без явной команды.
- ❌ Не использовать `any`, `// @ts-ignore` без критической необходимости.
- ❌ Не удалять существующий код без замены на функциональный аналог.
- ❌ Не запускать `git commit`, `git push`, `docker compose up` без подтверждения.

## 🔄 5. Протокол Выполнения Задач

### Шаг 1: Анализ
- ИИ читает ТЗ, сверяет с макетами и спецификациями.
- Выявляет недостающие данные (поля, эндпоинты, стили).
- Формулирует вопросы пользователю (если есть неясности).

### Шаг 2: План
- ИИ выдает краткий план:
  ```
  1. Создать/обновить файлы: [список путей]
  2. Изменить логику: [описание]
  3. Проверить: [команды/тесты]
  ```

### Шаг 3: Генерация
- Пошаговая правка файлов через KodaCode.
- Каждый блок кода сопровождается путем к файлу.
- После изменения → мгновенная проверка синтаксиса.

### Шаг 4: Верификация
- ИИ проверяет:
  - Соответствие макету
  - Типизацию (TypeScript strict mode)
  - Отсутствие `any`/`// @ts-ignore`
  - Соответствие API-спецификации
- При ошибках → автоматическая правка без лишних объяснений.

## 🧠 6. Управление Контекстом в KodaCode

### 6.1. Инъекция Контекста (В начале сессии)
```markdown
# PROJECT CONTEXT: Balloo Messenger
- Stack: Next.js 15, Prisma, PostgreSQL 16, Native Node.js WebSocket, MinIO
- UI: CSS Modules + Styled Components, Octagon avatars, Square bubbles (cut corners), Dark/Light/Russian themes
- DB: `mockups/data_schema.json` (PK: cuid, timestamps: BigInt/Unix)
- API: `docs/04-api-websocket-spec.md` (REST + WebSocket)
- Auth: NextAuth v5, JWT (access 15min, refresh 7d), 2FA (email-код), OAuth (Yandex, Mail.ru, Rambler)
```

### 6.2. Поддержка Контекста (При работе с модулем)
- При генерации экрана: загружать соответствующий `mockups/<node>/<screen>.html` и `.md`.
- При работе с БД: загружать `mockups/data_schema.json` + `docs/03-database-schema.md`.
- При работе с API: загружать `docs/04-api-websocket-spec.md`.

### 6.3. Сжатие Контекста
- Если сессия длинная → ИИ автоматически архивирует старые блоки кода в комментарии или временные файлы.
- Ключевые решения фиксируются в `docs/01-architecture-decisions.md`.

## 📝 8. Шаблоны Команд (Промпты для KodaCode)

### Генерация экрана
```
Сгенерируй экран `<node>/<screen>.html` из `mockups/`. 
Используй компоненты из `@balloo/shared` и стили из `common.css`. 
Верни полный код файла с путем. Без пояснений.
```

### Настройка БД
```
Создай Prisma-модели для таблицы `<table_name>` согласно `mockups/data_schema.json`. 
Генерируй миграцию и seed-данные из `pre_filled_data.json`. 
Верни только код файлов.
```

### Написание API-роута
```
Реализуй серверный роут `/api/v1/<path>` согласно `docs/04-api-websocket-spec.md`. 
Используй Prisma, Zod-валидацию, NextAuth сессию. 
Верни код файла и тесты.
```

### Отладка
```
Запусти `pnpm dev` и покажи логи ошибок. 
Найди причину сбоя в последних измененных файлах. 
Предложи точечную правку. Верни исправленный код.
```
