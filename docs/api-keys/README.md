# API-ключи balloo — карта получения

Папка `docs/api-keys/`: по файлу-анкете на каждый внешний провайдер, который
balloo использует или может использовать. Анкета отвечает на вопросы «где
регистрироваться, что именно выдаётся, куда вписать, что проверить, что сломается
без этого».

**Секретов здесь нет и быть не должно.** В анкете — только публичные идентификаторы
(`CLIENT_ID`, `SHOP_ID`, номер счётчика Метрики) и ссылки на кабинеты.
`CLIENT_SECRET`, `API_KEY`, `SMTP_PASSWORD`, `VAPID_PRIVATE_KEY` живут исключительно
в `docker/prod/.env.production` на сервере.

## Как читать

1. Ниже — раздел «Сводка»: кто готов, кто пуст, кто недоступен.
2. Свой контур env — раздел «Где живут ключи»: какие переменные из какого файла
   читаются. Ошибётесь контуром — получите «ключ есть, а кнопки нет».
3. Собираетесь получить новый ключ — открываете файл анкеты по порядку приоритета
   (`01_yookassa.md` … `17_yoomoney.md`) и делаете по шагам «Процедура получения».
4. Получили — правите статус в своей анкете и строку в «Сводке» этого README.

## Где живут ключи

| Файл | Кто читает | Назначение |
|---|---|---|
| `docker/prod/.env.production` | `docker-compose.prod.yml` (`env_file`) | **единственный источник для прода**. Здесь и секреты |
| `docker/prod/.env.production.example` | человек | шаблон, секреты заменены на `***` |
| `packages/backend/.env` | backend в разработке | локальные значения, в git не попадает |
| `packages/admin/.env` | админка в разработке | то же для админки |
| `.env.example` (корень) | человек | общий шаблон, заполнен частично — **не является источником** |

Правило: значение, добавленное только в `.env.example`, в проде не существует.
После получения ключа — правка `docker/prod/.env.production`, затем
`docker compose --env-file docker/prod/.env.production -f docker-compose.prod.yml up -d`,
затем `systemctl restart balloo` (если поднят systemd-юнит) и проверка из анкеты.

## Правила, которые нарушать нельзя

1. **Никогда не коммитить секреты.** Проверка перед коммитом:
   `grep -nE "(SECRET|API_KEY|PASSWORD|PRIVATE_KEY)=" <файл> | grep -v "=\s*$" | grep -v "\*\*\*"`.
2. **Один провайдер — один рояль.** Секрет YooKassa не едет в `.env` админки.
3. **Не печатать ключи в логах и в выводах скриптов.** `console.log(process.env.YOOKASSA_API_KEY)`
   — авария.
4. **Утечка = немедленная ротация у провайдера**, а не «перезапись файла». Порядок:
   перевыпустить ключ у провайдера → вписать новый в прод → перезапустить →
   отозвать старый.
5. **Права на файлы:** `chmod 600 docker/prod/.env.production`.
6. **Режим ключа должен совпадать с контуром:** тестовый `test_…` ключ YooKassa в проде
   даёт приём платежей на тестовом же кассовом счёте.

## Процедура получения ключа (общая, для всех анкет)

1. Открыть анкету, прочитать раздел «Что нужно от balloon заранее» (редирект-URI,
   домены, e-mail владельца, ОГРН/расчётный счёт — где требуется).
2. Зарегистрировать приложение/магазин в кабинете провайдера **от имени владельца
   проекта**, не от личного аккаунта (иначе отзыв 2FA/смены пароля блокирует прод).
3. Выдать минимальные права: OAuth-приложению — только email+имя; платёжному ключу —
   только платежи, без прав на выплаты/возвраты, если возвраты делает UI.
4. Вписать значение в `docker/prod/.env.production` (не в `.env.example`).
5. Перезапустить сервис и выполнить проверку из раздела «Проверка после вноса»
   анкеты. Не «кажется работает», а конкретный curl/действие в UI.
6. Обновить статус в анкете и в «Сводке» этого README.

## Чего мы сознательно НЕ получаем

- **MAX** — публичного OAuth-протокола для сторонних сайтов у MAX нет; переменные
  `MAX_*` в проде пусты и кодом не читаются. См. `10_max.md`.
- **Яндекс Диск** — файлыballoo отдаёт с MinIO по подписанным URL, Диск не нужен.
  См. `11_yandex_disk.md`.
- **Slack** — уведомления идут в само приложение и в Prometheus-алерты. См. `12_slack.md`.
- **YooMoney** — легаси-набор переменных, кодом не читается; платёжка — YooKassa.
  См. `17_yoomoney.md`.
- **Telegram / VK Pay / Sber ID / Google** — интеграции нет, переменных нет.
  Анкеты нужны, чтобы решение «не делаем» было зафиксировано, а не потеряно.
