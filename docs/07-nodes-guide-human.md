## 1. Общая архитектура монорепо

Бalloo — это монорепо, содержащее 12 узлов (доменов), каждый из которых представляет отдельный сервис или приложение:

```
balloo/
├── mockups/                    # ИСТОЧНИК ПРАВДЫ — макеты экранов
│   ├── shared/                 # Общие экраны (ошибки, офлайн, бан)
│   ├── balloo-su/              # Основной мессенджер
│   ├── admin-balloo-su/        # Админ-панель
│   ├── command-balloo-su/      # Портал сотрудников
│   ├── features-balloo-su/     # Фич-реквесты
│   ├── history-balloo-su/      # История версий
│   ├── download-balloo-su/     # Загрузки
│   ├── docs-balloo-su/         # API документация
│   ├── mobile/                 # Мобильные макеты
│   ├── desktop/                # ПК обёртки
│   ├── specifity-balloo-su/    # Спецификация
│   ├── blog-balloo-su/         # Корпоративный блог
│   └── assets/                 # Общие стили и скрипты
├── packages/                   # Код приложения
│   ├── web/src/                # Веб-клиент (balloo.su)
│   ├── desktop/src/            # Desktop-клиент
│   ├── mobile-android/         # Android-клиент
│   ├── mobile-ios/             # iOS-клиент
│   ├── server/src/             # Бэкенд
│   └── shared/src/             # Общий код
├── docs/                       # Документация
├── tickets/                    # Мультитикеты
└── docker/                     # Docker-инфраструктура
```

### Классификация узлов

| Тип | Узлы | Назначение |
|---|---|---|
| **Клиентские** | у_01, у_08, у_09 | Пользовательские интерфейсы мессенджера |
| **Административные** | у_02, у_03 | Внутренние инструменты управления |

| **Справочные** | у_10, у_11 | Спецификация и блог |

## 2. Система нумерации

Все объекты проекта имеют уникальные ID в формате `z_xx_yy`:

| Префикс | Тип | Пример | Описание |
|---|---|---|---|
| `у` | Узел (node) | `у_01` | Узел balloo.su |
| `0` | Функция (function) | `0_01_03` | Функция №3 узла №1 |
| `1` | Экран (screen) | `1_01_04` | Экран №4 узла №1 |
| `2` | API-эндпоинт | `2_01_05` | Эндпоинт №5 узла №1 |
| `3` | Сущность данных | `3_01_02` | Сущность №2 узла №1 |
| `4` | Компонент | `4_01_01` | Компонент №1 узла №1 |

- `xx` — номер узла (00–11)
- `yy` — порядковый номер внутри узла (01–99)
- ID не меняются при правках, не переиспользуются

```bash
# Установка всех зависимостей монорепо
pnpm install

# Или через npm
npm install

# Или через yarn
yarn install
```

### Запуск dev-сервера

```bash
# Запуск всех пакетов (монорепо)
pnpm dev

# Запуск конкретного пакета
pnpm --filter @balloo/web dev
pnpm --filter @balloo/server dev
pnpm --filter @balloo/desktop dev
```

### Запуск конкретных узлов

```bash
# Веб-клиент (balloo.su)
pnpm --filter @balloo/web dev

# Сервер
pnpm --filter @balloo/server dev

# Desktop
pnpm --filter @balloo/desktop dev
```

### Запуск Docker-инфраструктуры

```bash
# Запуск всех сервисов (PostgreSQL, Redis, WebSocket)
cd docker && docker compose up -d

# Остановка всех сервисов
cd docker && docker compose down
```

## 16. Примеры кода для типичных задач

### Создание нового экрана

```
1. Создать HTML-файл в соответствующем каталоге mockups/<узел>/<экран>.html
2. Создать MD-документацию рядом: mockups/<узел>/<экран>.md
3. Обновить index.html (каталог экранов)
4. Обновить index_ecrans.md (метаданные)
5. Обновить index_ecrans.json (структурированные метаданные)
6. Обновить docs/ если функция влияет на архитектуру/API
```

### Создание нового компонента

```
1. Создать каталог: mockups/components/<name>/
2. Создать HTML: mockups/components/<name>/<name>.html
3. Создать MD: mockups/components/<name>/<name>.md
4. Использовать common.css и common.js из mockups/assets/
```

### Использование shared-компонентов

```javascript
// В коде приложения (packages/)
import { Error404, Error500, Offline } from '@balloo/shared/components/errors';
import { BanAppeal } from '@balloo/shared/components/ban';
```

### Подключение WebSocket

```javascript
// В коде приложения (packages/)
import { createWebSocket } from '@balloo/shared/utils/websocket';

const ws = createWebSocket({
  url: 'wss://api.balloo.su/ws',
  onMessage: (event) => {
    // Обработка входящих сообщений
  },
  onOpen: () => {
    // Подключение установлено
  },
  onClose: (code) => {
    // Соединение закрыто
  }
});
```

### Работа с темами

```css
/* В CSS-файле компонента */
:root {
```
