## 2. Дефекты, подтверждённые строками

1. **Секция «Аккаунт» у авторизованного показывает сырые ключи.** Пункты заданы
   `RightMenu.tsx:73,74,76` ключами `menu.profile`, `menu.settings`, `menu.accounts`;
   рендер — `t(item.key as TranslationKey)` (`:268`). В словаре этих ключей нет:
   `grep -c "'menu.profile':" packages/shared/src/i18n/translations.ts` → `0` (то же для
   `menu.settings`, `menu.accounts`). `t()` на отсутствующий ключ возвращает сам ключ
   (`translations.ts:2582-2583`: `if (!translation) return key`) → в меню буквально `menu.profile / menu.settings / menu.accounts`.
2. **TypeScript это не ловит.** `RightMenuItem.key` объявлен `TranslationKey | string`
   (`RightMenu.tsx:28`), а в рендере — приведение `as TranslationKey` (`:268`, `:240`).
   В union `TranslationKey` есть только `menu.balloo|admin|command|features|history|download|docs|
   button|themeDark|themeLight|themeRussian` — трёх ключов нет.
3. **`scripts/check-i18n.cjs` слеп к таким ключам:** он ищет только литералы
   `t('…')`/`translate('…')` (`scripts/check-i18n.cjs:45` — регулярка `\b(?:t|translate)\(\s*'([a-z0-9.]+)'`), а ключи меню приходят через props.
   Прогон `node scripts/check-i18n.cjs` → «использованы в коде, но не определены: 0» при
   трёх битых подписях. Отсюда зелёный CI и «P38 готов» в статусе.

## 3. Чего из P38 нет в коде

1. **Мобильное бургер-меню (≤768px) — отсутствует целиком.** Подтверждения отсутствием:
   - `packages/ui/src/styles/` содержит только `chrome.css` и `themes.css`; файла `topbar.css` нет;
   - `grep -rn "right-menu__overlay\|right-menu__switcher\|right-menu__back\|right-menu__title\|
     right-menu__header\|right-menu__footer\|right-menu__submenu--theme\|right-menu__submenu--lang"
     packages/ui/src packages/web/src` → ноль совпадений;
   - `grep -rln "max-width: 768px" packages/ui/src packages/web/src --include=*.css` →
     только `chat.css`, `global.css`, `specifity.css` (правого меню не касаются).
   Всё, что описано в P38.1/P38.4/P38.5 (оверлей `z-index:999`, панель 320px с
   `translateX(100%)→0` 0.3s, подменю `max-height 0→144px`/`0→216px`, switcher с
   `.toggle--on`, скролл-лок, ESC, клик-вне) — из утраченного `mockups_new`, в коде не реализовано.
2. **Техподдержка в меню отсутствует** — и это соответствует действительности:
   `grep -n "support" packages/web/src/router/index.tsx` → пусто, маршрута `/support` в web нет
   (в эталоне пункт есть — `common.js:496-497`). Требуется либо экран+маршрут, либо решение
   владельца вычеркнуть пункт из контракта.
3. **«Мультиаккаунт» ведёт на `/profile`** (`RightMenu.tsx:76`) и отсутствует в эталоне
   (`common.js:513-519` даёт Профиль/Настройки/Выйти). Отдельного экрана `/accounts` в web нет.

## 4. План (по порядку, каждый шаг проверяем)

1. Добавить `menu.profile`, `menu.settings`, `menu.accounts` в union `TranslationKey` и в словарь
   (20 локалей, как у соседних `menu.*`). Проверка: `node scripts/check-i18n.cjs` (0 расхождений) +
   `pnpm build` (union-тип заставит проверить все места использования). **Тестов в пакете
   `@balloo/ui` нет** (`grep -rln "describe(" packages/ui/src` → пусто), так что тест на рендер
   подписей придётся писать — иначе шаг нечем доказать.
2. Расширить `scripts/check-i18n.cjs`: собирать ключи, переданные через props/массивы
   (`key: '…'` в `*.tsx`), иначе класс дефектов остаётся невидимым.
3. Решить по Техподдержке (экран vs вычеркнуть) и по «Мультиаккаунту» (отдельный экран vs убрать пункт).
4. Внести макет-кит в репозиторий (перелить архив) и только после этого заводить тикет на
   мобильное бургер-меню — сейчас сверять не с чем.
