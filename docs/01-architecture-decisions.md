# Архитектура проекта Balloo Messenger

> **Версия:** 1.0 | **Дата:** 2026-07-30  
> **Статус:** Документация завершена

## 📦 Стек технологий
- **Монорепо:** pnpm workspaces
- **Frontend (Web):** React 18 + Vite + TypeScript
- **Desktop:** Electron + Vite + TypeScript
- **Mobile:** Expo (React Native) + TypeScript
- **Backend:** Express.js + TypeScript + WebSocket (ws)
- **Database:** PostgreSQL 16 (собственный, не Supabase)
- **ORM:** Prisma
- **Realtime:** WebSocket (ws package)
- **CI/CD:** GitHub Actions + Docker Compose
- **Тесты:** Jest + RTL, Playwright, Supertest
- **Мониторинг:** Winston + Prometheus / Grafana
- **Админ-панель:** Отдельный сайт в монорепо (`admin.balloo.su`)

---

## 📝 Принятые архитектурные решения

### 1. База данных и ORM
- **Собственный PostgreSQL 16** (не Supabase) — самостоятельный сервер в Docker
- **Prisma** для типобезопасного ORM и миграций (Prisma Migrate)
- **Конвенции:** PK `String @id @default(cuid())`, timestamps `BigInt` (Unix seconds), FK `<refTable>Id`
- **81 таблица** в схеме, 10 seed-таблиц с предзаполненными данными
- **Schema файл:** `mockups/data_schema.json` (источник правды по данным)

### 2. Аутентификация
- **JWT + refresh tokens** (access 15 мин, refresh 30 дней)
- **OAuth:** Yandex ID, VK ID, Mail.ru ID
- **2FA:** TOTP (Google Authenticator) + backup codes
- HTTP-only cookies, SameSite=Strict, Secure flag
- argon2 для хэширования паролей

### 3. Realtime-коммуникация
- **WebSocket (ws package)** для сообщений, presence, typing
- Подключение с JWT-авторизацией (query param token)
- Heartbeat (ping/pong каждые 30 сек)
- Room management по chatId
- 24 WebSocket-события

### 4. Mobile стратегия
- **Expo (React Native)** для iOS и Android
- Единая кодовая база для мобильных платформ
- Биометрия (Face ID / Touch ID)
- Deep Linking (`balloo://chat/123`)

### 5. Backend архитектура
- **Express.js** для REST API
- Версионирование: `/api/...`
- Zod-валидация всех запросов
- Middleware: auth, rateLimit, validation, CORS, errorHandler

### 6. Desktop архитектура
- **Electron** — основной Desktop-клиент
- Переиспользование `packages/web/src/` через workspace
- System tray, native notifications, menu bar
- Сборка: .exe (NSIS/MSI/portable), .deb/.rpm/.AppImage/.tar.gz, .dmg/.zip

### 7. Структура фронтенда
- **Shared компоненты:** Бизнес-логика и UI-кит в `@balloo/shared`
- Платформенно-специфичные обёртки для каждой платформы
- Zustand для state management
- React Router v6 для навигации

### 8. State Management
- **Zustand** — лёгкое управление состоянием приложения (чаты, сообщения, сессия)

### 9. Интернационализация (i18n)
- **20 языков (3 группы):**
  - Русские (15): RU + 14 языков народов РФ (TT, BA, CE, CV, AV, DAR, UDM, LEZ, KBD, CHM, OS, SAH, BUA, UK)
  - Дружественные (3): ZH, HI, BE
  - Остальные (2): EN, FR
- **Эталон:** `mockups/data_schema.json` → `conventions.languages`

### 10. Деплой и CI/CD
- **Docker Compose на одном сервере** (простой деплой, v1)
- **GitHub Actions** для CI/CD пайплайна
- **v2:** Kubernetes для оркестрации контейнеров

### 11. Тестирование
- **Jest + React Testing Library** — юнит и компоненты
- **Playwright** — e2e тесты
- **Supertest** — тестирование API
- **Turborepo** — параллельный запуск в монорепо

### 12. Логирование и мониторинг
- **Winston** — логирование в приложении
- **Prometheus + Grafana** — метрики и алерты
- TTL логов: **30 дней** + ротация
- **Админ-панель** (`admin.balloo.su`) — отдельный экран для health checks и метрик

### 13. Кэширование
- **Next.js ISR/SSR** — серверный рендеринг с инвалидацией
- Минимальная зависимость от внешних кэшей на старте

### 14. Безопасность
- **JWT** — access token (15 минут TTL) + refresh token (7 дней TTL)
- **HTTP-only cookies** для токенов, SameSite=Strict, Secure flag
- **CORS + CSP** — заголовки безопасности
- **Helmet.js** — заголовки безопасности
- **Rate limiting** на API (login — 5 попыток/мин, капча после 3 неудач)
- **Блокировка сессии/IP** на уровне nginx
- **Zod** — request validation
- **CSRF protection** — CSRF tokens для форм
- **DOMPurify** — sanitize input (XSS защита)
- **Prisma ORM** — параметризованные запросы (SQL injection защита)
- **argon2** — хэширование паролей
- **Собственная капча** (серверная генерация, не reCAPTCHA/hCaptcha)
- **Шифрование диска (LUKS)** + шифрование чувствительных полей (email, токены)

### 15. UI Framework и Компоненты
- **CSS Modules** (локальные стили) + **Styled Components** (CSS-in-JS где локальные не оптимально)
- **Базовый каталог:** `/home/ivan/Рабочий стол/проекты/general_files/components/` — шаблонные компоненты (DynamicForm, DynamicTable, DynamicPage и др.) используются как основа, адаптируются под Balloo
- **Новые компоненты:** Avatar (октагон), MessageBubble (угловые срезы), ChatList, ChatWindow, MessageInput, EmojiPicker, ReactionPicker, ReplyPanel, FileAttachment, VoiceMessage, PollWidget, CallOverlay, StoryViewer, TabBar, DrawerNav, Sidebar, Topbar, SkeletonLoader, EmptyState, CodeBlock, MarkdownRenderer, QRScanner, FileUpload, Toggle/Switch, Select, TimePicker, RangeSlider
- Всё созданное и переиспользуемое отдаётся в каталог по правилам каталога

### 16. State Management
- **Zustand** — лёгкое управление состоянием приложения (чаты, сообщения, сессия)
- **React Query** — управление серверным состоянием и кэшированием API

### 17. Интернационализация (i18n)
- **Мультиязычность с первого дня — 20 языков (3 группы), подтверждено пользователем:**
  - **Русские (15):** Русский (RU) + 14 языков народов РФ: татарский (TT), башкирский (BA), чеченский (CE), чувашский (CV), аварский (AV), даргинский (DAR), удмуртский (UDM), лезгинский (LEZ), кабардино-черкесский (KBD), марийский (CHM), осетинский (OS), якутский (SAH), бурятский (BUA), украинский (UK)
  - **Дружественные (3):** Китайский (ZH), Индийский/Хинди (HI), Белорусский (BE)
  - **Остальные (2):** Английский (EN), Французский (FR)
- **Эталон перечня:** `mockups/data_schema.json` → `conventions.languages`

### 18. Видео/Аудио звонки
- **WebRTC + PeerJS / LiveKit**
- Поддержка **групповых звонков** (SFU-подход для стабильности)

### 19. Push-уведомления
- **Без сторонних SaaS-сервисов** (например, без OneSignal)
- Использование нативных/стандартных решений (FCM для Android/Web, APNs для iOS) без обёрток

### 20. Desktop (Electron)
- **Electron** — основной Desktop-клиент (Node.js-бэкенд, легче и проще Tauri)
- Переиспользование `packages/web/src/` через workspace
- System tray, native notifications, menu bar, window management
- Auto-updater (отложено в v2+)
- Сборка: NSIS (.exe), MSI, Portable (.exe), DEB, RPM, AppImage, TAR.GZ, DMG, ZIP

### 21. Offline Mode и Синхронизация
- **Очередь сообщений** — полученные сообщения кэшируются локально, отложенная отправка при потере связи
- Синхронизация при возврате в сеть

### 22. Роли и Права доступа
- **Для приложения:** Super Admin / Admin / Mod / Developer / Support / User
- **Для групп:** Создатель (полный контроль) / Админ (управление участниками/сообщениями + модератор) / Модератор (удаление сообщений) / Участник (базовые права) / Читатель (только чтение + реакции)
- **RBAC:** JSON-поле в БД (Prisma Json type) — flexible, матрица прав по отделам

### 23. Админ-панель (`admin.balloo.su`)
**Доступно:**
- **Пользователи** — просмотр, бан с аргументами (с подтверждением 4 другими администраторами), редактирование ролей
- **Метрики** — графики из Grafana, логи из Winston, нагрузка сервера
- **Настройки** — управление фичами (feature flags), глобальные уведомления
- **Доступ к файлам** — просмотр загруженных файлов (MinIO/Yandex Disk) — только статистика, без чтения содержимого

**Ограничения:**
- ❌ **Читальные чаты** — администраторы НЕ читают содержимое чатов, только статистика
- ❌ **Бан** — требует подтверждения 4 другими администраторами, активируется при минимум 5 жалобах от пользователей
- ❌ **Обжалование бана** — пользователь может обжаловать бан в течение 72 часов
- ❌ **Удаление групп** — только пустые группы

### 24. Codegen и Скрипты
- **Prisma Codegen** — типы из схемы БД
- **Commit hooks (Husky + lint-staged)** — линтинг и тесты перед коммитом
- **Docker build scripts** — автоматическая сборка образов

### 25. Структура монорепо (Feature-based)
- **Feature-based архитектура** — `/features/auth`, `/features/messaging`, `/features/groups` (по фичам, а не по типу)
- Каждый фич-фолдер содержит: components, hooks, types, api, tests
- Общая логика выносится в `@balloo/shared`

### 26. Offline Mode
- **SQLite (Web/IndexedDB)** — локальное хранилище для Web
- **SQLite (Tauri)** — локальное хранилище для Desktop
- **SQLite (React Native)** — локальное хранилище для Mobile
- Очередь сообщений: полученные сообщения кэшируются, отложенная отправка при потере связи

### 27. UI Kit / Дизайн-система
- **Модульная структура** — каждый компонент в отдельной папке (component/ + index.ts + styles.css + test.ts)
- **Design tokens** — CSS variables для цветов, отступов, шрифтов
- **3 темы с первого дня:** dark (по умолчанию), light, russian
- **Accessibility (WCAG 2.1 AA)** с первого дня

### 28. Миграции БД
- **Prisma Migrate** — дефолтный инструмент для миграций
- Flyway не используется

### 29. Docker Compose — сервисы и поддомены (v1)
**Основные сервисы (Docker Compose на одном сервере):**
- **balloo.su** — веб-клиент (Next.js)
- **admin.balloo.su** — админ-панель
- **command.balloo.su** — внутренний портал для сотрудников и найма
- **features.balloo.su** — описание функций + запросы фич от пользователей
- **history.balloo.su** — история версий мессенджера
- **download.balloo.su** — загрузки (десктоп, мобильные приложения)
- **docs.balloo.su** — документация API (Swagger/OpenAPI)
- **blog.balloo.su** — корпоративный блог

**Инфраструктура:**
- MinIO — объектное хранилище (кэш, аватарки, медиа)
- PostgreSQL 16 — основная БД
- Prometheus + Grafana — метрики
- SMTP (Maildev для dev, свой SMTP для prod)

**v2:** Kubernetes с несколькими репликами, sticky sessions, auto-scaling

- **Верхняя панель (Top Bar)** на всех платформах.
- **Левая панель (Список чатов):**
    - **Web/Desktop:** Статичная, ширина от 1/3 до 1/4 экрана.

- **Удаление аккаунта:** Анонимизация через 90 дней (чёрная аватарка-октагон, имя → «Удалённый пользователь», уведомление). (Ответ 120)
- **Сессии:** Неограниченно + список устройств. Управление через «Мои устройства» (переименование, остановка, детали). QR-привязка новых устройств (TTL 60 сек, одноразовый токен, подтверждение на обоих). (Ответ 117 — блокировка приложения: Нет)
- **Мультиаккаунт:** Неограниченное количество аккаунтов на одном устройстве. Только для основного узла balloo.su. Переключатель в правом меню (профиль). Чаты/контакты — свои у каждого аккаунта (только активный). Уведомления для всех аккаунтов с меткой. Тема/язык/устройства — общие. Переключение мгновенное (JWT-сессии хранятся). Отключение — сессия удаляется, данные остаются.
- **Анти-бот:** Email + собственная капча (серверная генерация) + подтверждение email по коду + лимиты.
- **2FA:** TOTP (Google Authenticator) + backup codes. Отправка кода подтверждения на email при входе с нового устройства или подозрительной активности.
- **Политика паролей:** Минимум 8 символов, кириллица или латиница, цифры, строчные и заглавные буквы, спецсимволы: *!№#-_+=, спецсимвол — не первый символ.
- **Хэширование паролей:** argon2.

### 73. Монетизация и Поддержка
- **Подписка (v2):** Платные функции определяются в v2 (отложено).
- **Поддержка:** Встроенный чат с поддержкой (тикеты, приоритизация).

## 🆕 Новые архитектурные решения (v1 — дополнение)

### ADR-2FA: Двухфакторная аутентификация (TOTP + backup codes)
- **TOTP** (Google Authenticator, Authy и т.д.) для всех пользователей (web, desktop, mobile).
- **Backup codes** — одноразовые коды для восстановления доступа (10 штук).
- Экраны: `1_01_30` (balloo.su), адаптации `1_08_13` (mobile), `1_09_09` (desktop).
- WebSocket event: `2fa.required`.

### ADR-Stories: Сторис пользователей
- **TTL 24 часа** (`expiresAt`), хранение медиа на **MinIO** (self-hosted).
- **Ответ на сторис** пересылается в чат через `replyToChatId`.
- **Визуальная система:** аватарки сторис — октагон с укороченными диагоналями (`--octagon-clip-stories`), НЕ заменяет основной `--octagon-clip` аватарок.
- **Переливающийся градиент** (`--story-gradient`) per-темы (dark/light/russian) вокруг непросмотренных сторис; анимация `story-shimmer`.
- Компоненты: `StoriesTray` (лента) + `StoryViewer` (полноэкранный просмотр с прогресс-баром, свайпом, навигацией).
- WebSocket event: `story.created`.

### ADR-Status: Статус сервиса в admin (не отдельный узел)
- **Статус сервиса (`service.balloo.su` / `у_12`) НЕ выделен в отдельный узел** — функционал перенесён в админ-панель (`у_02`, экран `1_02_26`).
- В описании экрана `1_02_26` фигурирует фраза «перенесён из у_12» как историческая справка.
- Real-time мониторинг узлов через WebSocket event `status.update`; time-series снимки в `service_status_snapshots` (health-check воркер, cron).
- Инциденты создаются/закрываются админом (`service_status_incidents`, `createdByAdminId`).

### ADR-Bots: Управление ботами (админ не удаляет)
- Админ-панель управляет ботами (список, токены, верификация), но **не удаляет ботов** — удаление доступно только создателю бота.
- Админ может отзывать токены (`bot_tokens`) и снимать верификацию, но не ликвидировать сущность бота.

### ADR-Maps: Интеграция с Яндекс Картами
- **Яндекс Карты (Map API)** — для отображения и передачи геолокации (ключ предоставляется отдельно).
- **Собственная капча** — серверная генерация, не reCAPTCHA/hCaptcha (вопрос 5.1.11 вопросника).
