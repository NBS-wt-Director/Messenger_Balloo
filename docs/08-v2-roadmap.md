## 1. 🔐 Аутентификация и безопасность (v2)

### 1.1. Госуслуги OAuth
- **Статус:** отложено до v2
- **Описание:** Авторизация через Госуслуги (v2) — не нужна на первом этапе
- **Затрагивает:** таблицу `Account` (добавить provider `"gov"`), эндпоинты OAuth

- **Описание:** SMS-коды для верификации — только email на первом этапе
- **Затрагивает:** интеграция с SMS-провайдером, новые эндпоинты
- **Ссылка:** вопрос 4.4.3 вопросника

### 1.3. E2EE (End-to-End Encryption)
- **Статус:** отложено до v2

- **Затрагивает:** архитектуру сообщений, WebSocket, клиентское шифрование
- **Ссылка:** п. 127 чек-листа требований

## 9. 🐻 Маскот и AI-агент «Балунишка» (v3)

> Записано 13.10.2026 по словам владельца. Это **концепт v3 (MVP3)**, не v1 и не
> v2. Фиксируется здесь, чтобы идея не потерялась и влияла на решения уже сейчас
> (например, на выбор ассетов в UI).

### 9.1. Кто такой маскот

- **Реальный маскот** — `assets/logos/mascot.png`: медведь в русской толстовке,
  имя **Борис**. Стандартный (бесплатный) вид.
- Эмодзи 🦊/🐻 в макетах (`mockups/assets/common.js`, экраны) — **условность
  периода прототипирования**, не финальный дизайн. В UI MVP1 эмодзи заменяются
  на картинку маскота (тикет `tickets/active/1791864003-brand-assets-404.md`).

### 9.2. AI-агент «Балунишка» (v3)

Маскот становится персональным AI-агентом пользователя. «Балунишка» — имя
агента-медведя; архитектура допускает **линейку зверей-агентов** (ему подобных).

**Контекст и функции:**

- Контекст агента — **чаты пользователя**.
- Помогает решать задачи, планировать, **предлагает ответы в чат**.
- Пассивный режим (базовая бесплатная версия): если собеседник приглашает
  пользователя на мероприятие, балунишка **сам проверяет другие чаты** — нет ли
  там конфликтующих задач/договорённостей — и даёт пользователю подсказку.

**Кастомизация вида (монетизация):**

- Стандартный медведь в русской толстовке (Борис) — **бесплатно**.
- Другие животные, одежда, предметы — **покупаются**.

**Анимация «танцы» (монетизация):**

- Балунишка умеет «танцевать»: часть движений бесплатна, дополнительные
  покупаются (числа фиксируются при проектировании v3).
- Комбинации движений агент **собирает сам**.

### 9.3. Что из этого следует уже в v1/v2

| Решение | Обоснование |
|---|---|
| В UI использовать `mascot.png`, а не эмодзи | чтобы v3-анимация наследовала тот же персонаж и тот же слот в UI (триггер правого меню, auth-экраны) |
| Не плодить визуальные «талисман-стиль» ассеты отдельно от маскота | линейка зверей v3 строится вокруг Бориса и его вида |
| Пассивный AI-режим в v3 завязан на чтение чатов пользователя | приватность: обработка на стороне пользователя/нашего сервера, без внешних AI-API (конвенция проекта: только self-hosted/российские решения, см. deferred-to-v2 v2-024) |

## 10. 📝 Примечания

1. **Все решения по v2 могут быть пересмотрены** при переходе в Фазу 4 (разработка v2).
2. **Архитектура v1 спроектирована так, чтобы v2-функции добавлялись без breaking changes.**
3. **2FA (email-код) — в v1, не TOTP.** Backup-коды не нужны (ответ пользователя на вопросы 4.2.3 и 4.2.4).
4. **Firebase (FCM) не нужна** — на первом этапе только Web Push API (вопрос 5.1.5).
5. **Госуслуги OAuth** — перенесены в v2 (вопрос 5.1.9).
6. **Desktop (Tauri) и Mobile (Expo) — в v1**, не отложены.
