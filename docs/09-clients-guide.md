## Что такое клиентские узлы

**Клиентские узлы** — это части монорепо, которые пользователь видит и с которыми взаимодействует напрямую. В Balloo их три:

| Узел | ID | Домен | Платформа | Экранов |
|---|---|---|---|---|
| **balloo.su** | у_01 | balloo.su | Веб-браузер | 41 |
| **mobile** | у_08 | balloo.su | Мобильное приложение | 23 |
| **desktop** | у_09 | balloo.su | Десктопное приложение | 23 |

Каждый клиентский узел:
- Имеет **свой набор экранов** с уникальными ID в формате `1_xx_yy`
- Подключается к **общему backend** (server)
- Использует **общие компоненты** (global) и **собственные** (private)
- Делит **общие экраны** (ошибки, офлайн, бан) из узла `shared` (у_00)

### Отличие от серверных узлов

| Тип | Узлы | Назначение |
|---|---|---|
| **Клиентские** | у_01, у_08, у_09 | UI для конечных пользователей |
| **Административные** | у_02 (admin.balloo.su) | Панель администратора |
| **Корпоративные** | у_03 (command.balloo.su), у_11 (blog.balloo.su) | Порталы сотрудников |
| **Сервисные** | у_04–у_07, у_10 | Фич-реквесты, changelog, API docs, спецификация |

## Структура монорепо

```
balloo/
├── packages/
│   ├── web/src/              ← balloo.su (у_01) — веб-мессенджер
│   ├── mobile-android/src/   ← мобильное приложение (у_08)
│   ├── mobile-ios/src/       ← iOS-приложение (у_08)
│   ├── desktop/src/          ← Electron-обёртка (у_09)
│   ├── server/src/           ← backend API + WebSocket
│   └── shared/src/           ← общие утилиты, типы, API-клиент
├── mockups/
│   ├── balloo-su/            ← 41 HTML-макет (у_01)
│   ├── mobile/               ← 23 HTML-макет (у_08)
│   ├── desktop/              ← 23 HTML-макет (у_09)
│   ├── shared/               ← 8 общих экранов (у_00)
│   ├── assets/               ← common.css, common.js
│   └── index_ecrans.json     ← метаданные всех узлов
└── docs/
    └── 09-clients-guide.md   ← этот файл
```

## Запуск и настройка окружения

|---|---|

| pnpm | 8+ |

| Redis | 7+ (опционально) |

### Установка

```bash
# 1. Клонирование репозитория
git clone <repository-url>
cd balloo

# 2. Установка зависимостей (pnpm workspaces)
pnpm install

# 3. Настройка окружения
cp .env.example .env
# Редактирование .env:
#   DATABASE_URL="postgresql://user:password@localhost:5432/balloo"
#   REDIS_URL="redis://localhost:6379"
#   JWT_SECRET="your-secret-key"

# 4. Применение миграций базы данных
pnpm db:migrate

# 5. Предзаполнение базы (seed)
pnpm db:seed
```

```bash
# WebSocket на ws://localhost:3000
```

## FAQ и типичные проблемы

### Вопросы по запуску

**Q: Не могу подключиться к базе данных**  
**A:** Проверьте, что PostgreSQL запущен и в `.env` указан правильный `DATABASE_URL`. Запустите `pnpm db:migrate` для применения миграций.

**Q: Сервер запускается, но WebSocket не работает**  
**A:** Убедитесь, что firewall не блокирует порт 3000. Проверьте CORS-настройки в `.env`.

**Q: pnpm install падает с ошибкой**  
**A:** Удалите `node_modules` и `pnpm-lock.yaml`, затем повторите `pnpm install`. Убедитесь, что используете Node.js 20+.

### Вопросы по макетам

**Q: Макет отображается некорректно**  
**A:** Проверьте, что `common.css` и `common.js` подключены. Используйте переключатель тем в `index.html` для проверки всех трёх тем.

**Q: Как создать новый экран?**  
**A:** 
1. Создайте HTML-файл в нужной директории (`balloo-su/`, `mobile/`, `desktop/`)
2. Скопируйте структуру из существующего макета
3. Создайте MD-файл рядом (`*.md`) с документацией
4. Обновите `index.html`, `index_ecrans.json`, `index_ecrans.md`

**Q: Как изменить дизайн-систему?**  
**A:** Изменяйте CSS-переменные в `mockups/assets/common.css`. Изменения затронут все макеты. Будьте осторожны — это глобальное изменение.

### Вопросы по разработке

**Q: Как добавить новый API-эндпоинт?**  
**A:** 
1. Опишите эндпоинт в `mockups/api_schema.json`
2. Обновите `docs/04-api-websocket-spec.md`
3. Реализуйте в `packages/server/src/`

**Q: Как добавить новую таблицу в базу данных?**  
**A:** 
1. Опишите таблицу в `mockups/data_schema.json`
2. Добавьте seed-данные в `mockups/pre_filled_data.json` (если нужно)
3. Создайте миграцию в `packages/server/src/db/migrations/`
4. Обновите `docs/03-database-schema.md`

**Q: Как работают темы оформления?**  
**A:** Три темы определены в `common.css` через CSS-переменные. Переключение происходит через добавление/удаление класса на `<body>`: `data-theme="dark"`, `data-theme="light"`, `data-theme="russian"`.

**Q: Как добавить новый компонент?**  
**A:** 
1. Создайте компонент в `packages/shared/src/components/`
2. Добавьте MD-документацию в `mockups/components/[name]/`
3. Используйте компонент в экранах

### Вопросы по архитектуре

**Q: Почему используется pnpm workspaces?**  
**A:** Для монорепозитория с множеством пакетов (web, mobile, desktop, server, shared) pnpm обеспечивает эффективное управление зависимостями и изоляцию пакетов.

**Q: Почему макеты — единственный источник правды?**  
**A:** Это позволяет отделить дизайн от реализации. Разработчик всегда знает, что именно нужно реализовать, глядя на макет. Документация и код — производные от макетов.

**Q: Как работают общие экраны?**  
**A:** Общие экраны создаются один раз в `mockups/shared/`. Все клиентские узлы ссылаются на них. В коде — через shared-компоненты. Это устраняет дублирование.
