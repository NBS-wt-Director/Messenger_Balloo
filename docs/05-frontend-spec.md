# AI-Agent: Frontend Specification

> Этот документ — спецификация для генерации UI-компонентов, страниц и дизайн-системы.

## 🌐 i18n — обязательное правило (решение владельца 26.11.2026)
> «Каждое слово текста должно быть снабжено переводом и зафиксировано в модуле
> переводов, хардкорить слова запрещено!»
> Тикет: `tickets/active/1795679146-i18n-no-hardcoded-strings.md`.
> Полное правило — `AGENTS.md` §«🌐 Правило i18n».

1. **Запрещён любой текстовый литерал в UI-коде**: JSX-текст, `title`,
   `placeholder`, `aria-label`, `alert`, `toast`, тексты ошибок, пункты меню,
   подписи кнопок, заголовки экранов. Только `t('namespace.key')`.
2. **20 языков** (`LANGUAGES`): ru, tt, ba, ce, cv, av, dar, udm, lez, kbd, chm,
   os, sah, bua, uk, zh, hi, be, en, fr. Каждый ключ обязан иметь все 20 локалей;
   fallback `en`/`ru` в `t()` — страховка, а не замена переводу.
3. **Перевод пишется вместе со строкой**, в `packages/shared/src/i18n/`.
4. **Неймспейсы по домену** (`settings.privacy.*`, `chat.attach.*`, `legal.*`,
   `errors.*`), чтобы ключ переиспользовался в web/desktop/mobile.
5. **Тип `TranslationKey` выводится из словаря** как `Record<Locale, string>` —
   пропущенная локаль = ошибка компиляции.
6. Правило действует на `web`, `ui`, `web-admin`, `web-features`, `web-history`,
   `web-download`, `desktop`, `mobile-android` и пользовательские тексты API.
7. Макеты (`mockups/`) — эталон формулировки на русском; в код текст попадает
   только значением ключа.

**Замер на 26.11.2026:** 228 файлов с кириллицей вне `t()` (web 135, mobile 34,
admin 28, desktop 22, features 5, ui 4); словарь — 133 ключа.

## 🧱 Единые требования ко всем узлам (решение владельца 26.11.2026)

> Разбор владельцем `features.balloo.su`, `history.balloo.su`,
> `download.balloo.su`, `api.balloo.su/docs` и настроек.
> Тикет: `tickets/active/1795683301-nodes-consistency.md`.
> Полное правило — `AGENTS.md` §«🧱 Единые требования ко всем узлам».

| № | Требование |
|---|---|
| U1 | **Шапка и подвал — единые**, из `@balloo/ui`, на каждом узле и экране (включая серверный HTML `api.balloo.su/docs`). Узел не рисует свою шапку/подвал. |
| U2 | **Прокрутка всегда и без полосы**: `height:100vh; overflow:hidden` → `.content{min-height:0}` → `.page-container{flex:1 1 auto; min-height:0; overflow-y:auto}`; полоса скрыта (`scrollbar-width:none`, `::-webkit-scrollbar{display:none}`). |
| U3 | **Горизонтальные отступы**: контент не касается краёв — минимум 24px (мобиле 16px), включая таблицы и широкие карточки. |
| U4 | **Статусы фич**: `реализовано` (протестировано) / `в процессе` (реализовано, не протестировано) / `в плане` + «волна N». Список не пустой. |
| U5 | **Пустое состояние**: объяснение + извинение + призыв к действию + кнопка «Что это?» с описанием экрана. |
| U6 | **Версии — только по команде владельца**: сейчас `MVP0` (первый деплой) и `MVP0.5` (текущая); новая — по фразе «MVP1 — закончен». |
| U7 | **Платформа без сборки**: плитка с текстом-извинением, без битой ссылки, через i18n. |
| U8 | **Дублирующая навигация запрещена**: есть боковое меню раздела — верхней панели тех же вкладок нет. |
| U9 | **Админка только в правом меню** (`ecosystem.ts`), в левой панели её нет. |
| U10 | **Новые истории** → бейдж на всех кнопках/пунктах «Истории» во всех меню. |

**Проверка:** шапка/подвал — нет собственной разметки; скролл — контент
прокручивается, полосы нет; отступы — скриншоты 360/768/1440 px; навигация —
нет двух одинаковых меню; пустые состояния — объяснение + действие + «Что это?».

## Дизайн-система (Ключевые принципы)

### Формы
- **Аватарки:** Восьмигранные (Octagon). Все круглые элементы → восьмигранные.
- **Пузыри сообщений:** Строгие прямоугольники с угловыми срезами. (Ответ 20)
- **Иконки:** Outline (тонкие контуры). (Ответ 21)
- **Модалки:** По центру экрана. Цвет рамки = статус. (Ответ 24)
- **Кнопки:** Primary, Secondary, Tertiary. Без скруглений. (Ответ 30)

### Стили
- **CSS Modules / Styled Components.**
- **Flat** — без теней, без Glassmorphism. (Ответ 26)
- **Темы:** Тёмная, Светлая, "Наша" (флаг РФ + драгметаллы). Синхронизация между устройствами.
- **Шрифт:** Google Fonts (Inter, Manrope). (Ответ 17)
- **Тени:** Flat — без теней. (Ответ 26)

### Бейджи уведомлений
- 1–9: число
- >9: точки
- >99: пустой квадрат с точкой в центре
- больше: закрашенный квадрат

### Состояния
- **Загрузка:** Skeletons. (Ответ 22)
- **Пустые состояния:** Тематические иллюстрации. (Ответ 23)
- **Скролл:** Бесконечный (infinite scroll). (Ответ 28)

## Навигация (Единая для всех узлов монорепо)

```
┌─────────────────────────────────────────────────────┐
│ [LOGO▼]  [Заголовок экрана (клик=обучение)]  [Действия▼]  [Маскот/Аватар▼] [Язык] [Тема] │
├──────────┬──────────────────────────────────────────┤
│          │                                          │
│ Левая    │                                          │
│ панель   │          Контентная область              │
│ (чаты/   │                                          │
│ список)  │                                          │
│          │                                          │
│ 1/3–1/4  │                                          │
│ экрана   │                                          │
│ (Web/    │                                          │
│ Desktop) │                                          │
│          │                                          │
│ Mobile:  │                                          │
│ сворачи- │                                          │
│ вается   │                                          │
│ влево    │                                          │
│          │                                          │
└──────────┴──────────────────────────────────────────┘
```

### Левое меню
- **Web/Desktop:** Статичная панель, ширина 1/3–1/4 экрана.
- **Mobile:** Скрывается влево, сворачивается до ширины иконок (аватарок).
- **Содержимое:** Список чатов, поиск, архив, контакты (зависит от страницы).

### Верхняя панель
- **Логотип (слева):** Выпадающее меню — навигация по узлам монорепо, общие страницы.
- **Заголовок экрана (центр):** Клик → режим обучения (тултипы + справка).
- **Кнопки действий (справа от заголовка):** Выпадающее меню (зависит от экрана).
- **Правое меню:** Маскот (гость) / Аватарка (авторизованный). Выпадающее меню: страницы/действия, язык, тема.

## Интерактивы (создание в чате)

### Команды
- `/poll_(вопрос;选项1;选项2;...)` — опрос
- `/quiz_(вопрос;选项1;选项2;...;correct=2)` — квиз
- `/list_active_(пункт1;пункт2;...)` — активный список
- `/list_passive_(пункт1;пункт2;...)` — пассивный список
- `/personali_(пункт1;пункт2;...;multiple=false)` — персонали

При вводе `/` над полем сообщения появляется интерактивная подсказка с типами и параметрами.

### Создание кнопкой
- Кнопка "Интерактив" в панели ввода → выбор типа → форма создания.

### Вложения сообщения — постоянные правила (решение владельца 26.11.2026)

> Правило действует для **всех** типов вложений, включая спроектированные в будущем.
> Тикет: `tickets/active/1795677071-unified-attachments.md`.

1. **Текст вложения ≠ заметка.** «Текстовые вложения» — это интерактивы: опрос,
   квиз, активный список, пассивный список, персонали (те же 5 типов, что в
   slash-командах), а не произвольный текст. Модалка «заметки» (`TextNoteModal`)
   не является отдельным типом вложения.
2. **Два равноправных пути к любому вложению:**
   - поле ввода сообщения — slash-команда (`/poll_`, `/quiz_`, `/list_active_`,
     `/list_passive_`, `/personali_`, и в будущем команды новых типов);
   - панель вложений (📎 / 🖼) — единый список всех типов.
3. **Slash-команда открывает форму** создания/загрузки выбранного типа, а не
   отправляет текст в чат.
4. **Одно сообщение — массив вложений разных типов.** Типы смешиваются в одном
   сообщении (фото + опрос + файл и т.д.).
5. **Лимиты (MVP1):** до **15** вложений в одном сообщении.
6. **Платные сообщения (MVP2):** до **50** вложений; свыше 15 — сообщение
   становится платным, стоимость `n + 5` баллов, где `n` — число вложений;
   пользователь получает предупреждение; свыше 50 — запрет.
7. **Новый тип вложения** обязан сразу поддерживаться в обоих путях (команда +
   панель) и попадать в общий массив `attachments`.

## 🆕 Новые UI-спецификации (v1 — дополнение)

### Stories (`StoriesTray` + `StoryViewer`)
- **StoriesTray** — горизонтальная лента аватарок сторис над списком чатов.
  - Аватарки — **октагон с укороченными диагоналями** (`--octagon-clip-stories`): диагонали в 3 раза короче прямых сторон. НЕ заменяет основной `--octagon-clip` аватарок профиля.
  - **Переливающийся градиент** (`--story-gradient`) per-темы (dark/light/russian) вокруг непросмотренных сторис; анимация `@keyframes story-shimmer`.
  - Просмотренные сторис теряют градиент (статичная рамка статуса).
- **StoryViewer** — полноэкранный просмотрщик:
  - Прогресс-бар сверху (сегменты по количеству сторис у автора), автопродвижение.
  - Навигация: тап слева/справа (mobile), стрелки (desktop), свайп.
  - Футер: поле ответа → `POST /stories/:id/reply` (пересылка в чат `replyToChatId`).
  - Закрытие: свайп вниз / Esc / клик вне зоны.
- WS event `story.created` обновляет ленту в реальном времени.

### 2FA-настройки (`TwoFactorSetup`)
- Экраны: `1_01_30` (balloo.su), `1_08_11` (mobile), `1_09_09` (desktop).
- **Включение:** Запрос на отправку email-кода → `POST /auth/2fa/send-code` → ввод кода из email → `POST /auth/2fa/verify`.
- **Отключение:** подтверждение email-кодом.
- **Механика:** Сервер генерирует одноразовый код, отправляет на email пользователя. Backup-коды не нужны. TOTP/Google Authenticator не используется.

### Календарь command (`CalendarView`)

### Cookie Banner и утилиты (CookieBanner, cookieUtils)
- CookieBanner: `packages/web/src/components/ui/CookieBanner.tsx` — всплывающее уведомление внизу экрана.
- Показывается при первом визите, если выбор по cookie ещё не сделан (`hasCookieChoice()` = false).
- Кнопки: «Принять все» (acceptCookieConsent + initYandexMetrika) и «Только необходимые» (declineCookieConsent).
- Согласие хранится в cookie `balloo-cookie-consent` на 365 дней, значения: `accepted` (аналитика + сторонние) / `essential` (только необходимые).
- Утилиты: `packages/web/src/utils/cookieUtils.ts` — setCookie, getCookie, deleteCookie, hasCookieChoice, hasCookieConsent, hasAnalyticsConsent, hasThirdPartyConsent, acceptCookieConsent, declineCookieConsent.
- Подключён в App.tsx после RouterProvider.

### Яндекс.Метрика (consent-based аналитика)
- Утилита: `packages/web/src/utils/yandex-metrika.ts` — lazy-load скрипта `mc.yandex.ru/metrika/tag.js`.
- ID счётчика: env `VITE_YM_METRIKA_ID` (число; пусто = Метрика не подключается).
- **Consent-based загрузка:** скрипт подключается ТОЛЬКО после «Принять все» в CookieBanner либо при старте приложения, если согласие уже дано (`hasAnalyticsConsent()` в App.tsx).
- **Анонимизация IP:** параметр `ip: true` в `ym(..., 'init', ...)` (требование 152-ФЗ).
- Параметры init: clickmap, trackLinks, accurateTrackBounce; webvisor отключён (приватность).
- SPA-навигация: после init патчатся `history.pushState/replaceState` + `popstate`, на каждую смену маршрута отправляется `ym(id, 'hit', path)` (trackPageview).
- Cookie Метрики (`_ym_uid`, `_ym_isad`, `_ym_d`) ставятся только после загрузки скрипта.
- Описано в политике cookies (`CookiesScreen.tsx`, разделы 2.3, 6).

### Сторонние cookie (OAuth, ЮKassa) — согласие
- OAuth-провайдеры (Яндекс ID, VK ID, Mail.ru ID) и ЮKassa ставят временные cookie на своих внешних доменах.
- Согласие на сторонние cookie фиксируется в cookie `balloo-cookie-consent` (значение `accepted`) на домене `.balloo.su` — проверка через `hasThirdPartyConsent()`.
- CookieBanner информирует о сторонних сервисах в тексте баннера; детали — в `/cookies` (разделы 2.4, 5, 6).
- Срок жизни внешних cookie: сессия авторизации (OAuth) / сессия оплаты (ЮKassa).

### Footer: морзе-тикер системных уведомлений (решение владельца 26.11.2026)

> Постоянное правило для подвала на **всех** экранах. Тикет:
> `tickets/active/1795677854-footer-morse-ticker.md`.

Две пустые зоны подвала — **не декор**, а системный тикер уведомлений,
кодирующий текст **азбукой Морзе** (последовательность точек и тире).

1. **Направление:** левый тикер бежит от левого края к центру, правый — от
   правого края к центру (сходятся в центре).
2. **Нет активных уведомлений (режим по умолчанию):**
   - левый — слоган «переверни общение!»;
   - правый — часовой пояс и предполагаемый город пользователя
     (например `UTC+5 Екатеринбург`).
3. **Есть активное уведомление:**
   - левый — источник (чат / группа / контакт / приглашение / вызов);
   - правый — тело уведомления.
   Уведомление приоритетнее режима по умолчанию.
4. **Планируемое обновление:** всем онлайн-пользователям через это поле
   показывается сообщение об обновлении.
5. **MVP2 — экстренные оповещения о ЧС (красный цвет):**
   - левый — район фактического местонахождения;
   - правый — предполагаемое реальное местонахождение.
6. **MVP4 — вычисление реального местоположения при VPN:** по группам,
   сообщениям и чатам определяем предполагаемое реальное местоположение, если
   замечен включённый VPN. **Никому не сообщаем** — только для адресной
   доставки сообщений и оповещений.

**Приоритеты режимов:** `emergency > update > notification > idle`.
Доступность: `prefers-reduced-motion` → статичный паттерн без анимации;
тикер не должен ломать раскладку на мобиле.
